# 面向408全范围的通用创作（实验阶段）

新路径把考查范围、材料获取、题目设计与可执行验证分开：具体考点无需新增生成函数；单选和综合题使用同一个引擎。原规则题及五考点创作保持不变。章节导航覆盖四科，不等于完整考纲的内容质量已经验证。

[样题](question-generalization-examples.md)包括八道接口测试题、两道依据网络补充材料编写的题和一道跨科环形缓冲区题，均由开发助手编写。模型实测另见[评测报告](question-generalization-evaluation.md)。

## 设计选择

旧创作入口复用规则题校验、固定材料标签与数值求解器，导致有新材料也无法创作新考点。新路径以材料实际解释的知识关系为依据，围绕可观察学习表现形成任务，不要求逐考点编写生成函数。

当前通用入口采用 v0.5。作者提交材料原文中的引文、学生可见条件、推导依赖及条件变化。程序检查引用、依赖、评分和可执行计算。题设表述与题面不同会记录为诊断，由审计区分同义表达和隐藏条件。v0.7 曾用编号材料和简化响应降低输入量，在四个生产模型配对任务中交付少于 v0.5，因此保留为实验记录。两处网络材料补充已单独保留。[对照结果](question-generalization-evaluation.md#v07deepseek-生产模型对照)

当前默认单候选、独立解答、反例审计。单候选是实验起点，不是能力上限或已证实最优策略。旧实测双候选没有救回额外请求，因此不先假设更多候选就更好。是否增加定向修复，应依据实际失败机制。

模型输出额度、超时和试验调用预算按运行环境与验收目标配置。阶段收官默认值为：作者 **32,768 输出 / 300 秒**、盲解 **16,384 输出 / 240 秒**、审计 **32,768 输出 / 420 秒**、计划 16,384 输出 / 120 秒；综合题评分点允许 **0.5 分**步长，小问分值与整题总分仍为整数。已发布的评测数字对应当次冻结的取值，后续对照可以调整。 首次 12 组诊断中，单独提高作者输出额度消除了当轮作者截断，进入盲解的候选仍为两臂各 7 份，严格可用题为 1 对 0。材料可追溯、独立解题隔离、验证通过后交 `PENDING` 是所有配置共同遵守的交付条件。 [模型输出配置](question-generation.md#输出与验收)

2026-11-12 阶段收官：`smoke-v3-final` 在同 8 题冻结清单上 PENDING **5/8**、技术完成 **6/8**（目标 7/8）；五道 PENDING 均独立复算正确，三轮合并 **6/8** 个槽位已有至少一道合格 PENDING。**通用命题生成与自检链路调优阶段正式结项。** 产出题包均按版本进入 `PENDING` 待审队列，后续工作转入审校模块联调与真人审校（当前 `human_review: UNVERIFIED`）。

v0.4独立解题只接收题型和学生视图，看不到教材、命题意图、作者答案、设计、评分点和见证。材料支持与命题目标由后续审计核对，避免解题阶段借助作者上下文补条件。单选重排选项，综合题逐问解答。审计尝试反例与替代读法，并核对解答等价性、引用支持、范围、约束、必要推理、条件变化、歧义、评分与见证对应关系。`answer_agreement`、`ambiguity`、`grounding`、`grading`、`witness_alignment` 是硬阻断；`reasoning_necessity`、`requirements`、`counterfactual`、`scope` 是软指标，未通过时照常交付并写入 `self_check.review_warnings`。模型判断仍可能有共同盲点。

## 调用方式

Pi工具、HTTP路径及外层题包不变。在`constraints.authoring`增加`syllabus_areas`选择新路径，`topic`是自由的具体任务名。

```json
{
  "schema_version": "0.1",
  "request_id": "topology-design-001",
  "subject": "data_structures",
  "topic": "topological_constraints",
  "question_type": "single_choice",
  "seed": 901,
  "constraints": {
    "requirements": ["同时考查合法序列的存在性与唯一性"],
    "authoring": {
      "objective": "design",
      "syllabus_areas": ["ds.graphs"],
      "focus": "区分有效、冗余与矛盾约束",
      "material_query": "拓扑排序 有向无环"
    }
  }
}
```

HTTP 服务可据 `material_query` 检索已配置的知识库和当前范围内的项目补充材料。显式`evidence`（含空数组）不被替换；无检索时可直接传原格式材料。新路径允许`rules=[]`，知识支持来自实际引文和语义核查；旧规则题的标签要求不变。

通用约束使用`requirements`文本数组；综合题另要求`total_score`（2至30的整数），通过`comprehensive`入口调用。批量/补题也可使用通用题，题目总分必须与槽位一致。原路径的数值约束如`page_size`保持原含义。完整直接材料示例：[单选](../question_generation/examples/general-authoring.json)、[综合题](../question_generation/examples/general-comprehensive.json)。示例中的自编材料明确标注来源，不冒充教材。

综合题保留`student_view.parts`、`instructor_view.parts`结构，加入小问依赖、评分点和等价方法。通用题支持[定向修订](#定向修订)。题目进入`PENDING`，学生展示使用`student_view`。新路径使用独立版本缓存键。

原TCP迁移考点的禁用检查仍保留；这不代表通用路径所有TCP信息可见性问题已经解决。

## 材料发现及边界

显式 `material_query` 启用材料发现。检索已登记、文档指纹匹配的教材，核对当前分块内容指纹并排除已标记冲突。使用中文二字片段、英文词和文档频率排序，无需额外检索服务。

信道容量和共享半双工碰撞时序已有三条带来源与内容指纹的项目释义，覆盖先前实测中的两个材料缺口。它们按章节与查询匹配，可与教材一起使用。未配置教材索引时，HTTP 服务也可返回命中的这三条释义。来源、定位和公式边界列于[样题](question-generalization-examples.md)。

后续按同一方式补充了单链表删除尾结点、三元组转置、阿姆达尔定律、SCAN 与 LOOK、曼彻斯特时钟同步。参见[具体考点取材复测](question-generalization-evaluation.md#粗需求优化器与材料发现)。

返回版本含`discovery: source-pinned; not chunk-curated`，表示来源和完整性核对，不表示片段已经人工审定或OCR完全正确。旧人工整理目录不会被自动扩充。模型遇到目录、缺图、冲突或缺关键规则，可返回`NEEDS_MATERIAL`及具体缺口。

已有具体考点和改述查询的字面命中探针。还需标注语义相关性和材料对推理的支持程度，才能估计正式召回率。同义词、OCR 误字和错误标题仍会造成漏检或噪声。纯英文内部考点名不自动翻译；用 `material_query` 给出教材用语，或者显式提供材料。跨科任务可指定最多四个章节范围，至少一个属于主科目。

## 可执行验证

复用原四类数值求解器，另增加`finite_domain`有限状态验证。用受限JSON表达整数运算、比较、布尔条件及全称/存在/计数查询，穷举声明的有限定义域。拓扑题可把顶点位置作为变量，加入位置互异和边的先后约束，再计数添加候选边后还有多少合法顺序，无需新考点生成模板。

上限为8变量、4096状态、512表达式节点，不执行模型代码。算术为数学整数，除法向下取整；机器溢出必须显式截断。无合法状态直接拒绝，不能利用空模型证明任意答案。

它只证明声明模型内的结论，不证明与题面一致，不证明无限规模复杂度或一般程序正确性。不适合枚举的题可不用它。题包`verification_scope`区分程序检查、模型判断和实际见证数量，不把空见证说成计算已验证。

## 与学生题面绑定的复算

通用请求可在 `constraints.authoring` 中显式设置 `public_scenario`。例如流水线综合题可用：

```json
{
  "objective": "analyze",
  "syllabus_areas": ["co.cpu"],
  "public_scenario": "pipeline",
  "material_query": "流水线 数据转发"
}
```

`pipeline` 支持五级顺序流水线的寄存器时序和转发比较，`selective_repeat` 支持按题设事件重放的简化选择重传。作者选择参数、目标及答案值。程序从同一组参数生成题干和问题，独立核对单选唯一答案或综合题每个目标的评分答案。程序在盲解前拦截不一致。学生仍只看到普通的题干和选项或小问，教师题包保留 `self_check.public_scenario_verification` 供复核。模型继续检查解析、材料支持和教学价值，题包仍进入待审。

这条路径适合把状态或周期作为可核对得分点。SR 模型要求实际发送的分组在该事件内到达，验证只覆盖题面列出的轨迹。流水线模型按题面明示的转发有效周期和寄存器写读先后计算。两类场景使用同一绑定逻辑，其他题仍走原通用创作。当前选型来自两个真实模型错例，验证使用脚本模型与程序复算。见[绑定复算结果](question-generalization-evaluation.md#题设绑定的离线回归)。

程序适合核对字段、ID、分值守恒、材料引用位置，以及能由学生可见输入和明确规则复算的状态或数值。题设绑定适用于可共用一套类型化输入生成题面和求解、且覆盖多个任务的场景。盲解和审计继续核对题意歧义、推理是否必要、引用是否支持规则、解析是否正确解释机制及评分是否接受等价解。期末 Cache 反事实可按题面离线复算，原审计已拦截该题，因此本轮沿用现有程序复算范围。

## 上游需求细化

Pi 可用 `question_generation` 的 `author` 操作把原始需求直接交给命题服务（提交 `792e5a6`）。HTTP 入口是 `POST /v1/question-generation/author`。

```json
{"schema_version":"0.1","request_id":"memory-practice-001","brief":"想练内存这块"}
```

只需 `schema_version` 和 `request_id`。无具体偏好可省略 `brief`，也可直接写「出一道 408 题」。已有参考材料可直接传 `evidence`，沿用来源、版本、定位、摘要和原文格式。可选 `subject`、`syllabus_areas`、`question_type`、`total_score`、`requirements`、`seed`。`syllabus_areas` 限定可选范围，若要同题考查其中多个章节，可在 `requirements` 写明。给出总分会固定为综合题。自动选择综合题时默认 10 分。省略种子时由请求 ID 稳定推导。

服务先搜集材料，再请模型提出考查计划，包括可观察的学习表现、任务及学生应给出的推理证据。无具体方向时，种子决定先查看哪个章节的材料。检索词只负责找到材料，具体考法由模型根据片段决定。短需求若匹配多个章节，会呈现各章节材料，例如「内存」可同时检索组成原理的 Cache 和操作系统的虚拟内存。显式 `evidence` 优先，空材料返回 `NEEDS_MATERIAL`。如果没有足以支持所需机制的材料，优化器可返回具体缺口。单选题只有题干和 ABCD 选项，计划中的 `student_evidence` 只描述选项要区分的核心判据与典型误解，不要求学生提交手写中间过程；综合题才要求中间状态、推导或论证。

固定科目、题型和唯一章节由服务填入。模型只能选择可用范围内的章节和确实提供的材料。原始需求与计划进入创作和审计，学生盲解仍只收到 `student_view` 和题型。成功题包仍为 `PENDING`，教师侧的 `generator.parameters.brief_plan` 和返回的 `authoring_report.plan` 可回看实际采用的计划。通常最多四次模型调用，成功结果按请求、材料快照和模型配置缓存。组卷补题及既有结构化入口沿用原契约。见[粗需求验证](question-generalization-evaluation.md#粗需求优化器与材料发现)。

### 单选题出题契约（禁自爆、防剧透）

`smoke-v3-final` 的三道单选入队题暴露了两类效果缺陷：错项在选项文本里写明「因为……」的荒谬理由，学生不计算即可排除；题干直接写出本应由学生推导的中间结论（例如「某两点不可比」「当前状态安全」），使题目退化为阅读理解。计划提示与单选视图提示现已写入三条硬约束：

1. **纯结果同构选项**：四个 `options[].text` 只能写同构的计算数值、状态序列、表项映射或具体操作，严禁附带「因为……」「由于……」「只要……就……」等解释性理由或因果论证；错因分析只写在 `instructor_view.option_explanations` 与 `misconceptions`。
2. **防单步秒排**：考多子项或多步结果时，正确项的第一个子项数值不得在四选项中唯一，至少一个错项共享该正确值；对比两个表/方案/序列时，测试输入须让两者在关键机制上产生非平凡差异（不同匹配长度、不同分支或不同冲突处理结果），禁止设成完全同构的冗余子项。
3. **题干反剧透**：`stem` 只给初始结构、参数、表项或代码，不写出应由学生推导的中间结论。

这些是提示词级的生成约束，不是程序校验：程序仍只保证结构、引文与分值守恒，是否真的需要实质推理由 `reasoning_necessity` 软指标与人工审校判断。审计提示同步收紧 `grading` 的失败条件——仅在标准答案或评分点 `expected` 本身错误、评分标准泄题、或拒绝声明了接受条件的合法等价解法时判 `passed=false`，分值分布与评分粒度的意见只写入 `issues`。

### 分值契约

请求未显式给出 `total_score` 时，服务在进入计划前先从 `brief` 和 `requirements` 的正则命中（`总分|满分|共` + 2–30 的整数 + `分`）读取用户写明的综合题总分，并把该值作为 `constraints.total_score` 传给计划阶段；未命中时在同一输入里注明「若设计综合题，各小问总分默认按 10 分设计」。计划完成后只把默认值（缺失时 10 分、命中时提取值）写入请求，不覆盖调用方给出的值。

创作结束后，仅当调用方**未显式**传入 `total_score` 时，服务检查作者自拟的小问分值是否自洽：每问 `score` 为正整数、该问 `scoring_points` 的 `points` 之和等于 `score`、全题总分在 2–30 分之间；满足则把 `constraints.total_score` 同步为该总分后再做结构校验，题包 `metadata.score` 也随之取该值。调用方显式传入 `total_score` 时仍严格要求相等，不符仍以「综合题总分与请求不符：设计 X 分，请求 Y 分」拒绝。该规则使浏览器试验台（表单不含 `total_score`）与结构化入口共用同一契约。

作者若返回完整的 `student_view`、`instructor_view`、`design`、`calculations` 四个字段但漏掉外层 `{"candidate": ...}` 外壳，服务自动归一为该外壳后再校验；若顶层恰为 `{"candidate": {...}, "calculations": [...]}`（把可选见证放到外壳同级），则把 `calculations` 移入候选（已有内层字段时不覆盖）后再校验。其他字段组合仍按创作结构错误拒绝。

材料引文校验同样按「防伪造」而非「防编号笔误」处理：某条 `claims[].quote` 若不在其 `evidence_id` 指向的材料中、却在**本题传入的另一条材料**中逐字存在，服务自动把 `evidence_id` 重绑定到实际包含该引文的材料（NFKC 压缩匹配，与引文校验同一判据）。只有本题传入的全部材料都不包含该引文时才拒绝，因此伪造引文仍被硬拦。

自动取材路径使用 `general-authoring-v0.5-brief-v2`。初筛可用释义正文中的连续字词匹配补进至多一条相邻释义，原查询标签仍可直接命中。计划可在所选章节内请求至多三个 `material_queries`，每条定位一个机制。原选材料与查询合计至多四项，二次检索无额外模型调用。每条补充查询先按精确锚点检索，未命中时回退到 related-notes 检索；若回退后仍未命中，只要已选材料非空就保留已选材料继续创作，并把缺口记录到 `authoring_report.material_query_gaps`，只有完全没有可用材料时才返回 `NEEDS_MATERIAL`。显式材料仍走原路径。[取材对照](question-generalization-evaluation.md#自然语言取材与定向修订)

## 定向修订

调用原 `POST /v1/question-generation/revise`，发送 `schema_version`、`request_id`、原始 `current_question` 题包及以下 `feedback`。在反馈中写清可复核的缺陷和受影响的位置。

```json
{
  "feedback_id": "review-001",
  "question_id": "原题的 question_id",
  "target_version": 1,
  "part_id": "p2",
  "action": "repair",
  "comment": "补充并列最小记录的选取规则，重新核对 p2 的答案和评分点。"
}
```

`part_id` 可用 `stem`、`question`、已有选项 ID 或小问 ID。服务按原引用恢复带指纹的教材和释义。若材料由调用方提供，传入含原引用的 `evidence`；服务取原题所引材料并核对出处、引文和已有指纹。成功时保留题目 ID、元数据和小问分值，生成第 2 版。字段变更后整题重新验证，盲解只接收新学生视图；绑定复算题继续从场景输入重建题面。待审表以原题包为条件原子替换，重试回读同一版。旧规则题继续使用原反馈动作。[修订验证](question-generalization-evaluation.md#自然语言取材与定向修订)
