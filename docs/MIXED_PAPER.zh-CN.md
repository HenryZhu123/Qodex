# 多学科整卷（本地验证版）

## 已实现

- 同一张卷可跨四科学科，混合 `single_choice` 与 `comprehensive`。
- schema_version=2.0 的 `slots` 是最终题目顺序；40个单选slot后可以接任意数量综合slot，总大题数不超过100。
- 每个slot独立指定原始总分；综合题可指定有序 `part_scores`，例如 `[3,7]`。省略表示不限制小问分配，仍校验题内小问与评分点分值守恒。组卷不改题、不缩放分值。
- 可选精确知识点与难度；未指定时不限制。每个slot必填学科、题型、分值。
- 单选支持2–26个选项；综合题保留共同题干、小问题面、逐问答案、评分点、等价方法与小问依赖说明。
- 文本参考材料与题面转义后输出，学生卷不含教师答案。每次成功结果仍保存独立学生/答案快照，原有历史接口不变。
- 一条损坏记录、状态404、答案不完整、小问分值不守恒等单独进入 `rejected_records`。其余合格候选继续组卷。
- 记录查询触及100条上限、状态查询网络失败、超过2000候选预算时，候选池标记不完整；如果仍无法组齐，只返回UNRESOLVED，不断言全库缺题。
- 导出前重查入选题目的 `task_id + question_id + version` 和PASS状态；失败时不导出。

## 兼容性补丁（2026-11-16 补测）

- v2 槽位同时接受既有确定性综合题的存储类型 `comprehensive_application`（服务端归一为 `comprehensive`，搜索时两者都查）。
- 确定性综合题的评分点 `expected` 可能是数字、dict 或 bool；转换时统一序列化为文本，仅影响导出/展示，不改题库快照。
- Pi 的 `exam_assembly` 工具会把 `data_structures` / `computer_organization` / `operating_systems` / `computer_networks`
  映射为题库中文标签，避免自然语言对话拿 syllabus ID 去查中文题库。
- `question_bank.search?question_type=comprehensive` 已同时覆盖 `comprehensive_application`（2026-11-16 晚）。
- 已知残余：重复题替换的端到端样本仍未取得；47 题全卷语义复核、前端未覆盖。

## 调用

接口仍是 `POST /v1/exam-assembly/assemble`，Pi工具仍是 `exam_assembly`。

```json
{
  "schema_version": "2.0",
  "request_id": "跨学科练习",
  "subject": "408计算机学科专业基础",
  "question_count": 2,
  "total_score": 12,
  "slots": [
    {"subject":"数据结构","question_type":"single_choice","score":2},
    {"subject":"操作系统","question_type":"comprehensive","score":10,"part_scores":[3,7]}
  ],
  "export_pdf": false,
  "similarity_decisions": []
}
```

不要同时传v1配额字段。v1单学科配额练习仍用原契约。

网页“智能组卷”默认进入“多学科整卷”，自定义表格从1道单选开始。独立的“408标准整卷”卡片提供“编辑此结构”和“一键生成整卷”：前者载入40道单选＋7道综合的可编辑配置，后者直接提交该预设（47题、150分），与下方自定义提交独立。预设的综合题分配、小问分值是可编辑示例，不宣称是真题固定结构，也不保证当前题库已经具备候选；题量不足仍返回真实缺题报告。

## 数据交接注意

已修复 `GeneratedQuestionImportService`：从命题包读取原始 `student_view.parts` 和 `instructor_view`，保存到不可变QuestionView的 `parts`、`grading`、`student_stem`；审校题面仍包含小问题面与分值。单选旧快照不增加空字段，保持原有内容核验。

旧综合题快照缺少结构化评分时不会猜测补齐。必须由命题模块产生新版本，再独立审校、入库；不得覆盖已存在的同一版本。无需新建数据库表，这些字段保存在现有JSON快照中。

## 边界

- v2直接生成HTML，可通过预览页浏览器打印PDF；`export_pdf:true`会被明确拒绝，未静默假装生成PDF。
- 图片/图形资源尚未接入受控渲染；含此类内容会隔离并说明，避免无图残缺卷。文本材料正常支持。
- 默认保留字面相似筛查；v2可选择全题对语义复核，确认重复后在同一候选池内按原槽位要求换题，仍不认证整卷语义质量。配置和预算见下节。v1保持原有字面筛查及人工复核流程。
- 单科知识点/难度的边际配额继续用v1。v2是精确有序slot约束，不自动把边际配额转成未授权的交叉配额。
- 本次验证使用离线合成记录，不调用付费模型、不写入真实题库；实际40＋7生成仍取决于正式题库的合格题量。

## 本地测试

1. 使用原有本地启动脚本，重启审校与组卷服务，使新快照字段与新接口同时生效。
2. 进入网页“智能组卷 → 多学科整卷”，先按本机题库实际分值配置少量题目。
3. 生成后在历史中分别预览学生卷、答案卷；检查材料、小问、分值和答案隔离。
4. 再使用40＋7配置；若缺题，查看缺口及rejected_records，不修改审校状态来凑数。

本版只在本地工作目录修改，等待用户确认后再提交到个人分支；未修改远程main。

## 可选语义复核与换题

v2请求增加 `semantic_review:true`、`semantic_max_calls`（默认8，0至100）、`similarity_search_limit`（默认32，1至128）。网页折叠面板与Pi工具均已接入，默认不开启。人工结论仍用 `similarity_decisions`，绑定题号、版本及包含材料/小问/答案的内容指纹。模型结论单独记录source=model，不伪装成人工。

模型需在根目录被忽略的 `.env.local` 显式配置 `EXAM_ASSEMBLY_SEMANTIC_ENABLED=1`、`EXAM_ASSEMBLY_SEMANTIC_BASE_URL`、`EXAM_ASSEMBLY_SEMANTIC_MODEL`、`EXAM_ASSEMBLY_SEMANTIC_API_KEY`；可设置 `EXAM_ASSEMBLY_SEMANTIC_MAX_CALLS`（默认8）。不自动借用其他模块密钥。现有一键启动脚本会传递这些变量，修改后需重启组卷服务。配置示例不包含真实Key。

实际请求上限取客户端与服务端两者较小值；每次最多4个题对，无自动重试，语义阶段总时限120秒。缓存仅存在于单次请求，换题后只复核新题对。题面过长、超时、返回截断/错误题号/过期指纹/不明确结论、预算耗尽或搜索上限均不生成完整试卷。停在可继续复核的状态，不能将部分覆盖当作全卷通过。

所有入选题对均覆盖，包含低字面相似度的改写题、共同材料和综合题小问。仅同知识点、共享材料或答案字母相同不能判重。确认冲突后分别尝试排除两端题目，避免单向排除把必须保留的题误删；不改变原学科、题型、分值、小问分配和可选知识点/难度约束。完整遍历候选冲突分支仍无法组齐才报告当前池无可行卷；搜索上限只返回UNRESOLVED，不证明全库缺题。

`semantic_review`报告保存模型原始可见输出/用量、内容指纹、人工与模型结论来源、尝试过的题目组合、最终换题位置及全题对覆盖状态。成功后的来源版本仍再次核验，历史仍用原有不可变快照。全题对复核通过不等于整卷质量通过，也未检测跨题答案提示。

47道题共1081对，默认8次模型请求最多覆盖32个尚未判定题对，无法保证在该预算内完成40＋7语义复核；应保留预算停止，不自动追加费用。大卷的检索候选缩减/批处理优化仍需独立评估覆盖率后再做。

2026-11-16小规模模型试验：12组AI辅助编写的开发题对，模型判断均符合开发预期标签；另验证重复概念题被不同任务题替换。共用7次请求（授权上限12），没有写入正式题库。不是独立教师标注评测集，不能声称真实题库准确率或40＋7全卷语义验证已经完成。
