> 均指该阶段。当前主路径（通用材料驱动创作：24 章节、单选与综合、粗需求入口、一轮定向修订）见
> [通用命题主线](question-generalization.md)。本页所述单选双候选路径仍在 `authoring.py` 中可用，但不再扩展。
> 测试数量、推理档和 Pi 等待时间已随之后阶段变化，见 [模块说明](question-generation.md)。

自主命题现在有两条共用交付接口的路径。原规则生成器适合低成本、可重复的基础练习；新增模型创作用于条件反推、错误诊断、边界迁移和方案设计。它实际读取教材摘要及已核验原文，并输出教学目标、逐项错误机制和可复算的计算记录。

本次没有引入训练、向量库、Agent 团队或执行模型代码。模型负责设计问题与解释，程序验证结构、证据引用和数值，另一次不看作者答案的调用独立解题。所有交付仍为 `PENDING`，不替代审校模块。

## 调用

沿用 `single`、`batch` 和 `replenishment` 操作。在单题或槽位的 `constraints` 中增加：

```json
{
  "authoring": {
    "objective": "analyze",
    "focus": "根据两条观测反推未知条件，避免直接套公式"
  }
}
```

`focus` 可省略，最多 500 字。保留原有 `page_size`、`cache_size` 等约束。不传 `authoring` 的请求保持原行为，包括原题目 ID。示例见 [authoring.json](../question_generation/examples/authoring.json)。

| objective | 实际考查行为 |
| --- | --- |
| `analyze` | 联立条件、反推未知量、比较机制 |
| `diagnose` | 根据错误输出定位可解释该现象的错误步骤 |
| `transfer` | 将规则用于新的边界条件或情境 |
| `design` | 选择满足目标的改动，或能区分不同解释的测试 |

v1.1 阶段沿用原有五个考点和单选题契约。**TCP 的 `transfer` 模型创作暂不开放**：真实实验发现信息可见性歧义，补充模型审计仍未识别。该请求返回 `UNSUPPORTED_REQUEST`，不调用模型、不读取旧缓存。TCP 原规则题及其他目标仍可用。该阶段的综合题和修订继续使用原规则接口；通用路径在此后加入模型综合题与定向修订。

### 配置与运行

模型凭据只配置在 Python 命题服务端，Pi 不需要密钥。将以下内容放入 Git 忽略的本地环境文件：

```dotenv
DEEPSEEK_API_KEY=填写本地密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
QUESTION_GENERATION_AUTHORING_CACHE=/absolute/path/to/authoring-cache.sqlite
```

2026-11-09 官方文档及账号 `/models` 核对：`deepseek-flash` 对应 DeepSeek-V4.1-Flash-1017。模型名可配置，不使用退役别名。[DeepSeek 官方 API](https://api-docs.deepseek.com/)

从仓库根目录导出本地配置后运行：

```sh
set -a
. .local/question-generation/upgrade/deepseek.env
set +a
python3 -m question_generation question_generation/examples/authoring.json
```

CLI 只预览，不入队。HTTP 服务仍按 [原服务配置](question-generation.md#pi-调用与待审表交接)启动，保留 PostgreSQL 和知识库环境变量；Pi 仍调用 `question_generation` 的 `single`。省略 `evidence` 时，HTTP 服务按原清单取材；显式空材料仍返回 `NEEDS_MATERIAL`。

材料可附 `excerpt` 原文，最多 12000 字。知识库只在原指纹核验成功后返回原文；超长分块仅返回原有摘要，不伪装成完整原文。模型调用会发送这些材料，按团队材料使用约定配置。题包只保存引用定位和指纹，不复制原文。

### 交付与成本边界

- 每题生成两个候选；结构、引用或数值不合格的候选不会进入盲解。盲解重排选项且不接收作者答案、解析、计算记录，防止照抄答案。
- 可答性、材料支持、约束匹配、目标匹配、深度和清晰性均须达到门槛；选定题再核对解析及错项解释。最多三次模型调用，没有隐藏的修复重试。
- 模型创作、盲解和审计使用 `high` 推理档（本节十组实验运行时为 `low`，推理档后在 `3c2a1f3` 调整为 `high`），输出上限 16384 token，响应上限 1 MB。成功缓存按推理档区分，空输出、截断或异常响应会返回失败。总用量包含模型推理 token。
- 每批最多两道模型题。模型槽位不沿用规则生成器每题八次的候选预算；失败或去重不足会保留缺口。规则槽位不受新增模型题量限制。
- 成功结果写入 SQLite 持久缓存。同一版本、服务地址、模型及完整请求命中后原样返回，不重复调用模型。种子只用于请求与选项重排，不保证外部模型在清空缓存后逐字复现。缓存应放在持久目录；同一个缓存文件串行化创作，适合小组课程服务，不面向高并发。
- Pi 等待时间可配置（v1.1 阶段默认 15 秒；工作树改为默认 600 秒），可用 `QUESTION_GENERATION_TIMEOUT_MS` 配置 1000～1800000 毫秒。两道题或较繁忙服务可设为 1200000。取消 Pi 等待不保证已开始的服务端计算停止，重试应使用原请求。
- `MODEL_UNAVAILABLE`、`AUTHORING_CACHE_UNAVAILABLE` 无题交付，单题 HTTP 返回 503。`SELF_CHECK_FAILED` 返回无题及自检原因。原请求可重试；未缓存的失败重试会重新调用模型。

题包保留 `student_view`、`instructor_view`、`evidence_refs`、`generator`、`self_check`、`review_status`，新增 `pedagogy`。**对学生只展示 `student_view`**；其他字段包含答案、错项机制或解题信息。

## 实验结果与实际提升

冻结十组输入，覆盖五个原有考点，使用同一份真实知识库材料生成规则基线和模型候选。每个考点两个预先指定目标；种子及所有原始响应保留在本地实验目录。未通过的样例没有从统计中删除。

| 指标 | 结果 |
| --- | --- |
| 原规则基线 | 10/10 生成；考法保持已有固定结构 |
| 模型原始候选 | 20 题；1 题结构不合格，8 题未达到盲解质量门槛 |
| 自动交付 | 6/10 请求；4 组因深度、目标匹配、材料覆盖或解析矛盾未交付 |
| 对自动交付结果独立复核 | 4 道数值题用另外编写的枚举/计算程序确认；1 道 TCP 设计题经本助手逐项复核可用；1 道 TCP 迁移题有歧义 |
| 已知漏检处理 | 新增信息可见性检查后仍漏检，故关闭 TCP 模型迁移入口；未声称提示词已解决问题 |
| 冻结实验资源 | 27 次调用，194628 token；每组累计调用耗时约 46～125 秒，均值约 99 秒 |
| 追加定向核查 | 3 次调用；与冻结实验合计 30 次、206952 token。不含前期开发试验 |

这是小样本的工程实验。五道复核可用题展示了新增考法，**不是“真实教学效果提升率”**。未进行真人教师盲评、学生答题、难度标定或区分度测量；同一模型跨调用仍会共享错误倾向。

两个候选在本轮没有挽救额外的请求：六道自动交付题均来自第一候选。因此本轮不能证明双候选比单候选更有效；已证明的增益来自材料参与设计与具体考法扩展，检查的价值体现在确实拦下了计算、解析和目标不匹配问题。

### 可直接比较的题目

原分页题给出完整页表，让学生拆地址、查表、计算物理地址。新题之一改为：

> 页大小 256 B，页号 0～5 对应的页框恰好为 {0,3,5,7,9,15}，且互不相同。已知页0→5、页2→0、页4→9；虚地址300→物理地址1836，虚地址1000→物理地址4072。求虚地址1400的物理地址。

答案为 **888**。必须先用两条观测反推页1→7、页3→15，再利用唯一页框集合推出页5→3，最后计算地址。另写程序穷举剩余页框的六种排列，只有一种同时满足观测。这不是只替换原模板里的数字。

原 Cache 题要求拆标记、行号、偏移。新诊断题给出两个输入 `0x0A3C`、`0x1A4C` 在 256 B、16 B 块的 Cache 中都被错误地放入第12行，要求定位错误机制。正确行号应分别为3和4，而两个地址低4位均为12；由两条观测定位“误把字节偏移当作行索引”。四个候选机制分别复算后，只有这一项解释全部观测。

其他可用样例包含按双目标选择只改一个页表项、用不同错误算法解释子网边界取错、设计能反驳“一次发送对应一次读取”的 TCP 实验。栈的本轮模型样例未达到交付门槛，仍可使用原有已验证的规则与综合题。

## 验证与维护

```sh
python3 -m unittest discover -s tests
```

v1.1 阶段结束时两套 Python 环境各 84 项测试通过，包含关闭 TCP 迁移入口和约束不能被忽略的回归检查。另对五考点各100个种子比较，500个旧请求返回的完整题包及 ID 与升级前完全一致。当前测试数量见[模块说明](question-generation.md)。

真实 Pi→HTTP→知识库→PostgreSQL 验证已回读 16 份完全一致的当前题包，覆盖原五类操作和新增创作题送审、重复入队、模型不可用不入队。创作题复用真实模型生成与盲解结果，进行了新的解析审计；集成测试禁用了外部 API，验证的是持久缓存与交付链路，不冒充新的模型生成实验。

本地实验与复验脚本位于 `.local/question-generation/upgrade/`：`run_holdout.py` 保留冻结输入且拒绝覆盖，`independent_check.py` 独立复算已交付数值题，`integration-run.sh` 创建并清理临时 PostgreSQL，原始记录包含材料，按本地资料管理。工作区恢复状态见上一级工作区的 `TASK_STATE.md`。

数值见证证明的是所列运算结果；与自然语言题意的对应及全部关键计算的覆盖仍由模型检查和后续审校承担。不要把 `self_check.status=PASSED` 当成数学形式化证明或正式审校通过。

## 设计依据

- [ACL 2025：基于学生选择预测的干扰项生成](https://aclanthology.org/2025.acl-long.1154/)及[公开实现](https://github.com/holi-lab/distractor-generator)：采用针对错误机制的错项解释；不引入需要 GPU 与学生选择数据的微调，未复制未明确授权的代码或数据。
- [BEA 2024：过生成与排序](https://aclanthology.org/2024.bea-1.19/)：借鉴有界候选机制；实际收益需在本项目单独验证，不能移植论文指标。
- [AIED 2024：不同 Bloom 层次的命题与评价](https://github.com/nicyscaria/AEQG_Blooms_Evaluation_LLMs)：采用可答性、清晰性、核心内容与教学可用性维度；不把自报层次当证据。
- [PrairieLearn AI 命题](https://docs.prairielearn.com/question/ai-generation/)与[生成、评分和测试接口](https://docs.prairielearn.com/question/server/)：借鉴创作与可执行验证分离，保留待审边界。
- [DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/)与[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)：严格处理空输出和截断，显式设置推理档位和预算。
