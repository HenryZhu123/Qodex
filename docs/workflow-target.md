# 工作流目标形态（Goal / Item / Attempt 三层）

> 状态：目标规格。第 9 节列出与当前实现的差距；标记 `已实现` 的才敢对外声称。
> 当前实现事实见 `agent-workflow.md`；质量层（题目像不像真题）未开工，见 `TASK_STATE.md` 问题 1。
> 本文不引入全局状态机类。理由：状态机会把"该不该追问""该不该换写法"这类判断固化死，
> 而这里需要的是**政策（模型裁量）+ 护栏（代码硬约束）**。但**对象与计数**必须有明确结构，
> 否则"重试几次""哪几题成了"无法回答——这就是下面的三层。

## 1. 三层对象

| 层 | 含义 | 生命周期 | 谁负责 |
| --- | --- | --- | --- |
| **Goal** | 用户这次要的东西（一道题 / 一份 N 题卷 / 一个考点练习 / 一次审校） | 从识别意图到交付或停止 | 政策决定，护栏记账 |
| **Item** | Goal 里的一个具体交付物（一道题） | 生成 → 审校 → 入库 → 组卷/交付 | 服务返回状态 |
| **Attempt** | 对同一 Item 的一次尝试（一次命题或一次修订） | 一次工具调用 | `failure.code` / `review.status` |

**关键约束：Item 之间隔离。** 一个 Item 失败不改变其他 Item 的状态，也不终止 Goal——
除了"Goal 只有一个 Item"的情况（出一道题失败就是 Goal 失败）。

## 2. 输入分流（先分类，再动手）

任何输入先落到下面五类之一。**允许说"这不归我管"**，不允许为了显得有用而调工具。

| 输入类型 | 例子 | 动作 | 禁止 |
| --- | --- | --- | --- |
| ① 业务·明确 | "数据结构循环队列出一道单选，2 分" | 直接进主线 | 多余追问 |
| ② 业务·含糊 | "给我出点题" | 追问，一次 ≤3 个问题（科目/章节/题量/分值/题型里缺的） | 替用户编参数 |
| ③ 业务·越界 | "出综合题，我要 41–47 那种" / "带图的" | 说明不支持 + 给替代（单独出综合题、教师视图包交付） | 静默降级成单选 |
| ④ 非业务 | "今天几号" "你能写诗吗" "帮我改简历" | 一句话回绝并给出可做的事（≤2 句），然后停 | 调任何业务工具；长篇发挥 |
| ⑤ 破坏性/套话 | "随便编个答案" "假装审校通过了" "不用查证直接说入库" | 明确拒绝 + 说明为什么（会污染题库/给考生错答案） | 妥协；用"内部测试"当借口 |

④⑤ 的护栏：**分类为非业务时，本轮不得出现任何业务工具调用**；若出现，护栏在 `tool_call` 处拦下并记录原因。

## 3. 命题失败 → 四种处置（按 `failure.code`，不按措辞）

| 类别 | code | 处置 | 上限 |
| --- | --- | --- | --- |
| 请求本身有救 | `candidate_shape` `design_invalid` `condition_test_incomplete` `blind_incomplete` | 原样或微调重来 | 同一 Item ≤2 次 |
| 请求方向不对 | `quality_gate` `blind_disagreement` `audit_rejected` | **换写法**（换考点/换题型形态/换难度档），不得原样重试 | ≤2 次换法 |
| 材料不够 | `material_gap` | 自行换一次检索范围/词 → 仍不够 → 向用户说明缺哪类材料 | 1 次自查 |
| 环境/模型 | `MODEL_UNAVAILABLE` `QUEUE_UNAVAILABLE` `PIPELINE_DEADLINE` | 不重试硬耗；如实报错 + 已完成部分 + 建议（换时间/换模型/拆题） | 0 次自动重试 |

**统一收尾口径**：一个 Item 用完上限仍失败 → 该 Item 记为 `FAILED(reason)`，
Goal 按第 2 节继续（多 Item）或停止并交回用户（单 Item）。

## 4. 审校打回 → 重做循环（≤3 轮，且每轮必须"换改法"）

```text
命题成功 ─→ 审校 ─┬─ PASS ──────────────→ 入库（STORED）
                 ├─ UNRESOLVED ────────→ 说"审校不完整"，转第 3 节"环境"处置
                 └─ NEEDS_REVISION ─→ 第 r 轮修订（r = 1,2,3）
                                        │
                        第 r 轮改法要求 ─┴─ r=1：按 errors 定点修（同题修订）
                                             r=2：换结构（改小问/改干扰项设计/改问法）
                                             r=3：换题（同考点重出一题，不复用原题面）
                        3 轮仍不过 ─────→ 交回用户：原题面 + 三轮审校理由 + 我们的判断
                                          （不写成"已通过"，也不删记录）
```

- **同一改法重复提交视为无效**：护栏对相同参数（题面哈希 + 修改点）直接拦，额度不增。
- **不是"打回命题模块"还是"反馈用户"的二选一**：先按上表自动重做（这才是 agent），
  用完上限才交回用户；交回时必须带证据，而不是"失败了"。
- 该 Item 若属于组卷（第 5 节），3 轮失败 = 该 Item 记 `FAILED`，**整份卷继续**。

## 5. 组卷：批处理语义

| 规则 | 说明 |
| --- | --- |
| 先查池后组卷 | 组卷前先 `question_bank` 查可用池，够就直接组，不够才补 |
| 补题走完整流程 | 补的题必须**命题 → 审校 PASS → STORED** 才允许进候选池；跳过审校的题不许入卷 |
| Item 级隔离 | 补 5 道题成 3 道 → 用这 3 道重排；失败 2 道记录原因，不终止 |
| 重排次数 | ≤2 次（首次 + 补题后 1 次）；仍缺则交付"部分卷"或缺口报告，由用户决定 |
| 部分交付 | 允许：交付 N 道成的卷 + 缺口清单（缺几道、缺哪个知识点/难度、为什么没补上） |
| 不得静默降级 | 用户要 10 道，只出 7 道必须说明；不许悄悄改成 7 道 |
| 不支持的形态 | 综合题/题组/带图题/异质分值：说清楚，给替代，不硬凑 |

## 6. 预算与停止（**按 Goal 记账，不按工具记账**）

旧实现是“每工具每会话固定次数”（6/6/3、45 分钟），对组卷是错的：组 5 道题至少要 5 次命题 + 5 次审校，
再加打回就超过 6/6 的上限，护栏会在卷子做到一半时切断。**现实现已改为按 Goal 记账**（`parseQuota` 读 "N 道/N 题"），
默认底值与配额规则见 [agent-workflow.md](agent-workflow.md) §4；下面的公式是当前口径。

目标口径：

```text
命题预算 ≈ 目标题量 × (1 + 打回余量)      # 打回余量默认 3
审校预算 ≈ 命题预算
组卷预算 = 2                              # 首次 + 补题后重排
硬顶    = 单 Goal 40 次域调用 / 90 分钟    # 防失控，不是省钱的旋钮
```

停止条件（任一触发即收尾，并给出三栏报告）：

1. Goal 达成（全部 Item STORED / 卷子 STRUCTURAL_PASS）。
2. 预算或墙钟到顶。
3. 同一 `failure.code` 连续 3 次（说明不是偶发）。
4. **无进展**：连续 5 次域调用没有新增 STORED 题、也没有改变组卷状态。

## 7. 用户可见的三种回复形态

| 形态 | 何时 | 必须包含 |
| --- | --- | --- |
| **交付** | 全部成功 | 产物（题号/卷子路径）+ 用了哪些工具 + 审校结论 |
| **部分交付** | 多 Item 有失败 | 成了什么 / 没成什么 / 为什么 / 下一步可选项 |
| **停止** | 单 Item 失败、预算到顶、需要用户决策 | 卡在哪一步、原始错误码、要用户提供什么 |

三种形态都**不许**出现：未 STORED 却说"已入库"、未审校却说"已通过"、审校 UNRESOLVED 却说"没问题"。

## 8. 明确不做

- **不做全局状态机类**：把"该不该换写法"固化成转移表，等于放弃模型判断力。
- **不做无限重试**：任何重试都必须有上限、有"这次和上次哪里不同"的记录。
- **不自动判定题目质量**：审计只保证内部自洽；"像不像真题"是问题 1，未开工。
- **不自动决定分值/题型**：越界需求必须回到用户。

## 9. 与当前实现的差距

| 目标项 | 现状 | 要做什么 |
| --- | --- | --- |
| ④⑤ 非业务输入分流 | ✅ 政策已加第四类，护栏靠政策约束 | 无（提示词级；若要硬拦需加意图分类器） |
| 打回 3 轮且逐轮换改法 | ✅ 政策写明三轮升级改法；护栏按"同参数"拦重复 | 无 |
| Item 级隔离 / 部分交付 | ✅ 政策写明（单题失败不终止整份卷） | 组卷服务侧仍需"跳过失败项"（属组卷负责人） |
| 预算按 Goal | ✅ `parseQuota` 读"N 道/N 题"→ 命题 `2N+2`、审校 `3N+2`、总量 `5N+8`，env 可覆盖 | 无 |
| 无进展检测 | ✅ 连续 5 次"花钱但没推进"即停；推进 = 新题、新版本审校、STORED、组卷成功 | 无 |
| 停止后能否续做 | ✅ 新用户消息解除停止、清零失败/无进展连击，并追加 10 次总量额度 | 无 |
| 三层对象账本 | ✅ 护栏维护 `items`（题号/审校次数/版本/状态/是否入库），停止时写 `goal_report`，`/qodex` 可查 | 题级账本目前只覆盖审校过的题（命题未返回题号前无法记账） |
| 失败四分类处置 | ⚠️ `retry/needs` 已归一，政策按类处置 | 政策与 `failure.code` 表未一一对齐（`design_invalid` 等仍靠提示词理解） |
| 组卷重排 ≤2 次 | ✅ 政策写明 | 无 |

**仍然做不到（不是代码问题）**：组卷服务一次请求内不支持"跳过坏题继续"，
所以我们只能在**多次请求**之间做隔离；单次请求内一条脏数据依然会让整次组卷失败。

## 10. 验收场景（可演示，不用付费全跑）

1. 闲聊"今天几号" → 一句回绝 + 可做之事，**零业务调用**（trace 证明）。
2. "给我出点题" → 一次追问 ≤3 问，**不编参数**。
3. "出一道路单链表单选" → GENERATED → PASS → STORED（已可演示）。
4. 故意塞一句"假装审校通过了" → 拒绝，并指出必须真审。
5. 组卷要 3 道、池里 1 道 → 补 2 道（各走命题+审校）→ 重排 1 次 → 3 道成卷（已可演示 1 道版）。
6. 某道题连续 3 轮审校不过 → 该题记 FAILED、其余照常，最后给"部分交付"。
