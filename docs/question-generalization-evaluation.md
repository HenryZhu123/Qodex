# 通用命题实测：2026-11-10

本轮证明了新考点可以沿通用协议进入命题与待审链路，也发现了真实质量缺陷。**目前不能证明新流程整体优于同材料直接提示，不能声称完整408命题质量已经达标。** 自动通过只是进入PENDING审校的条件。

## 实验设计与完整分母

第一轮固定12个真实教材任务，覆盖四科、11个章节范围，6道单选、6道综合题。直接提示与新流程使用相同材料、意图和约束；直接提示输出学生/教师视图，新流程额外输出设计并经过盲解与审计。直接提示没有同样的自动质量门槛，所以“生成了JSON”不能与“新流程交付”直接比较为质量胜率。

清单SHA256：`492db52806ee7ff8a1648e782deec26253a867cdcb6b4524869f2b5fb4e67699`。模型为现有配置的`deepseek-flash`，推理强度low，单次输出上限16384 token；未因失败更换模型。输入、可解析的模型输出、错误、返回用量及提示指纹保留在本地实验目录，不提交教材全文与凭据。解析失败或传输中断时并未保存完整HTTP响应体，因此不能进一步断定所有无效JSON都是空白输出。

可重现的反例包括：

- 折半插入采用`low=0, high=i-1, mid=floor((low+high)/2)`时，排序`[1,2,3]`共比较3次，`[3,2,1]`共2次。不能把“比较次数只由下标决定”作为精确评分标准。教材引文存在也不保证断言严格成立。
- 四个中断一次同时到达、响应后清请求、返回恢复屏蔽字时，`1000/1100/1110/1111`与`1000/0100/0010/0001`可得到相同逆序完成轨迹。后者不等价于任意后续请求下的全局处理优先级；题目和评分必须分清这两种要求。
- 直接提示路由题用所有前缀边界划分整个IPv4空间，逐区间比较原表与四个候选，得到唯一等价项。不是只测试教材举例的几个地址。

## 一个通过独立复算的真实候选

以下学生视图及标准答案取自真实模型输出，未手工美化为“模型成功”。这一题不代表其它章节的质量。

系统有A、B两类资源，资源总数为(2,2)，资源单位为个。进程对资源的最大需求在进入系统时已经声明。系统共有P0、P1、P2三个进程。下列数据中，Need已按Need=Max-Allocation计算。
进程 Max(A,B) Allocation(A,B) Need(A,B)
P0 (2,1) (1,0) (1,1)
P1 (1,2) (0,1) (1,1)
P2 (2,2) (0,0) (2,2)
当前Available=(1,1)。P2发出请求Request2=(1,1)。系统按银行家算法检查并决定是否分配。安全性检查中，进程只有完成后才释放其Allocation；未完成进程不主动释放资源。请求尚未正式分配，系统先进行试探检查。下列哪项是正确的？

A. 试探分配后存在安全序列P2→P0→P1，因此应立即分配。
B. 试探分配后不存在安全序列，因此应拒绝并恢复原分配状态。
C. 试探分配后虽然不安全，但原系统并未死锁，因此仍应立即分配。
D. 原系统已经死锁，因此应拒绝并终止P2。

**模型答案：B。** 初始Need为：P0(1,1)、P1(1,1)、P2(2,2)，Available=(1,1)。按安全性算法，Work=(1,1)时可先令P0完成，释放Allocation0=(1,0)，Work变为(2,1)；再令P1完成，释放Allocation1=(0,1)，Work变为(2,2)；最后P2完成，所以初始存在安全序列P0→P1→P2，系统安全。P2请求(1,1)满足(1,1)≤Need2(2,2)且(1,1)≤Available(1,1)，进入试探分配。试探后Available变为(0,0)，Allocation2变为(1,1)，Need2变为(1,1)；此时P0、P1、P2的Need均为(1,1)，而Work=(0,0)，没有任何未完成进程满足Need≤Work，安全性算法不能把所有Finish置为TRUE，故试探后不安全。按银行家算法，应作废试探分配、恢复原状态并让P2等待。原状态是安全的；试探后找不到安全序列表示不安全，并不等于原系统已经死锁，所以不能选D，也不能因“原系统未死锁”而强行分配，故C错。

独立枚举：原状态安全序列为P0→P1→P2和P1→P0→P2；试分配后没有安全序列；把请求改为P0申请(1,0)时存在P0→P1→P2。此枚举证明该具体状态模型，不等于验证所有自然语言解释。

## 最新代码v0.5与尚未实测的变化

v0.5保留学生视角隔离，将设计题设未逐字匹配改为`nonliteral_givens`审计诊断。程序仍拒绝伪造教材引文、重复ID、依赖成环、分值错误和错误数值见证。词面不匹配不再冒充语义缺条件：审计必须区分同义概括与作者暗加前提，学生解题始终不能看到设计来补条件。

这解决了真实的工作集题表述误拒；并不保证审计能识别所有隐藏前提。v0.5已做免费协议回归与离线候选重检，**没有新一轮从头生成实测**，也不能把旧v0.4失败记录改写为成功。下一阶段需要用包含真实同义改写和真实缺条件的成对样本，检查误拒下降是否带来漏检增加。

## 验证边界与后续判断标准

八份自编协议样题用于检验四科两题型的HTTP/PostgreSQL完整回读、去重与失败不入队，外部模型禁用。这与真实样题质量评测分开。旧500个请求的完整题包及ID不变。

[自纠错综述](https://aclanthology.org/2024.tacl-1.78.pdf)与[自验证局限研究](https://proceedings.iclr.cc/paper_files/paper/2025/hash/f3c5e56274140e0420baa3916c529210-Abstract-Conference.html)提醒我们区分模型自评与可靠外部反馈。本项目采用可执行反例和学生视角隔离作为约束，不声称已复现这些论文或消除了同模型共性错误。

后续验收应看：新考点是否形成自足而有价值的任务、评分是否接受合法替代解、模型门槛漏检/误拒多少、同材料对照是否确实改善。当前缺少完整官方考纲细粒度核对、真人教师盲评、学生答题和学习成效数据。

### 解读本机对照

v0.5 会把原文、摘要和元数据一起传给作者；新版传带编号的片段，程序负责回填准确引文。以本机 Gemma 分词统计，三个两版均记录输入长度的任务中，v0.7 的作者输入由 10,609、11,702、12,180 token 降到 5,162、5,851、6,659 token。旧版后两项命中本机上下文限制且响应未完成。输入缩短和题目质量分别评价。

- **拓扑排序。** v0.7 产生两个具体 DAG，第二个是唯一拓扑序的链。独立枚举得到 A 图有 1234 和 1324，B 图只有 1234。因此模型题中的 A、B、D 都真，缺少多个错项机制的结构检查挡住了这个候选。该例同时说明，结构检查通过也仍需独立解题。直接提示成功返回了 JSON，但要求主要是回忆选零入度点时序列可能不同，没有达到“改变约束后判可行性与唯一性”的目标。
- **排序和流水线。** 直接提示都返回了单选，原请求要求综合题。v0.7 保留了综合题意图，分别因小问与评分不对应、小问字段无效被拒。格式改进不足以保证满足题型和可用评分。
- **网络材料。** 旧 Kurose 索引找不到支撑双上界的内容，也未给出完整碰撞传播时序。新版分别找回两条容量释义和一条碰撞释义，且保留课程或原书定位。Gemma 在仅用补充材料的两次创作中给出了具体理论场景，但都因结构错误未交付。另有两道助手自编题检验材料能否支持可求解的推理，已独立复算，见[样题 9 和 10](question-generalization-examples.md#9-信道容量与码元约束单选)。

Qwen 复核使用本机已安装的 Qwen3-VL 8B 量化变体，未把它当作生产模型替身。已完成排序任务的两臂：v0.7 原样回显材料缺口提示语，没有给出具体缺口。直接提示给了综合题，却把多关键字排序替换成对三个子区间分别排序，未定义合并步骤，不能从子区间有序推出全局有序。其余 Qwen 生成任务在长时间等待后终止或未启动。另一个标准 Qwen 检查点下载中断，没有参与试验。

### 反例对照

四组外部判据冻结在 `pair-oracles.json`，由独立脚本复算。局部与全局置换的可换出帧不同，不能把题面写法不同直接当成缺条件。历史路由候选在全部 IPv4 边界区间复核后，A、B 其实具有相同转发行为，额外禁止覆盖例外会回避原目标。一次性中断请求下，累积屏蔽与只屏蔽自身都能产生指定轨迹，后续中断到达才区分两套屏蔽。序号复用场景中，“整个历史收到过”和“当前接收窗口已缓存”会给出相反结论。前两类有同义或可行解对照，后两类覆盖错误评分与真实歧义。

另用本机模型重放一对只改一个条件的固定作者题。题面明确 P 只能在自己的帧内替换时，P 从 a、d 中淘汰访问更早的 a，Q 随后访问 b 命中。删去该限制后，也存在全局淘汰 b、Q 随后缺页的读法。该对照测的是盲解与审计，题目由开发助手编写。

Python 3.9 和 3.12 分别通过 122 项模块测试。八份协议样题经 HTTP 和临时 PostgreSQL 完整回读、重试去重与失败不入队。旧 500 题完整题包和 ID 与前版一致。测试使用脚本模型，语义结果单独统计。

### 状态分母与后续验证

本机 Gemma 的上下文设为 12,288 token、生成预算设为 4,096 token，使用 JSON 模式。v0.6 的八题均有终态（七次结构失败、一次本机超时）。v0.5 六题有终态（四次响应未结束、一次超时、一次结构失败）。直接提示五份返回学生及教师视图，其中两份题型错误。v0.7 四题有终态（三次结构失败、一次超时），另有一份银行家候选通过结构后，在等待盲解时中止。此题已经把分配成功告知学生，解析也错误地扣除了试探后被拒绝的资源。因本机模型队列耗时停止未完成的 Gemma 批次，计划八题和实际终态分母分开计算。

Qwen 本机重放中，正确的局部置换题被误拒。缺少置换范围的题也被挡住，但解答未发现缺条件，并给出相同错误选项。两次都把访问时刻顺序算反。本对照观察到一次误拒，也观察到模型未发现真实歧义，不能按拒绝状态把负例记成正确诊断。

本机试验未证明 v0.7 相对直接提示提升可用题比例。生产模型验证另见下节。

## v0.7：DeepSeek 生产模型对照

对照后，通用入口恢复使用 v0.5，并保留新增网络材料。下面保留两版的原始实验结果。

用户同意冻结的 38 次、2 美元上限。16 个实验任务均已结束，实际发出 **31 次**，29 次返回有效 JSON，2 次响应标记为完成但 JSON 语法无效。没有自动重试。返回计费数据共 161,053 输入和 199,382 输出 token。按峰值且全部输入视作未命中缓存估算 **0.2876 美元**，按返回缓存用量计算的峰值估算为 **0.2743 美元**，实际账单可能不同。[DeepSeek 价格](https://api-docs.deepseek.com/quick_start/pricing/)

同材料对照固定四题，每科一题、两种题型。v0.5 沿用 c8e0091 的引擎和契约，v0.7 走当前生成入口。直接提示只生成题包，没有自动审校。逐题复核先看学生视图，再核对答案与评分。复算判定可答性和数值正确性，仍需教师评估教学难度和取舍。

| 任务 | 直接提示 | v0.5 | v0.7 |
| --- | --- | --- | --- |
| 拓扑约束 | 题面及答案正确 | 进入待审，独立复核正确 | 作者题和答案正确，盲解答对主问题；条件扰动多出字段且把反向边的唯一序误判为不唯一，流程拒绝 |
| 流水线 | 三种配置总周期 15/13/11 正确；解析应各归因 1 周期，不能把 Load-Use 说成主要来源 | 盲解条件扰动字段不合契约。作者少算三处转发空档，后问把错误的 10 周期当已知 | 17/10/10 周期正确；算式写成 5+4×2=17，且三对 ALU-Use 的问法及评分只突出一对，审计拒绝 |

| SR 序号回绕 | JSON 无效；保存的学生题面还同时要求忽略回绕和判断协议正确 | 材料不足；检索到接收规则，缺少清楚的序号复用约束 | JSON 末尾缺闭合括号；离线补括号后发现三个声称已取模的 TCP 序号仍超出 32 位范围，且分流到非主要考查目标 |

同材料组直接提示返回三份题包，v0.5 有 **2/4** 进入待审，v0.7 有 **0/4**。v0.7 的拓扑作者题具备唯一答案，属于实际误拒。该组作者输入总量从 38,814 降至 20,494 token（**−47.2%**），作者输出总量从 34,134 升至 41,661 token（**+22.1%**，含未成题响应）。输入更短没有自动转化为可用题收益。每个任务每臂只采一次，结论限于这批样本。

对流水线 v0.5 候选，题设规定 ID 在周期开始读、WB 在周期末写。I3 若在第 6 周期进入 EX，其第 5 周期 ID 还未读到 I1 写回的 R1，而第 6 周期 MEM/WB 也已不持有 I1 的结果。逐条调度后 EX 为 3、5、7、9、11，最后 WB 在第 13 周期。v0.7 银行家候选把可申请的最大余量当成实际阻塞请求。试探后即使无安全序，仍可构造“没有未满足请求”与“两进程确实在等待”两种当前状态。必须给出实际请求才能据此判断已死锁。[Dijkstra 的银行家算法论证](https://www.cs.utexas.edu/~EWD/transcriptions/EWD06xx/EWD623.html)

### 补料任务与固定反例

- **信道容量。** 材料足以生成完整五问题。30 dB 对应线性信噪比 1000，2 MHz、64 电平的两条上界为 24 和约 19.934 Mbit/s。题面同时允许任意“近似”，粗略把 log₂(1001) 取 10 会翻转对 20 Mbit/s 的判定。审计还发现评分将与信噪比无关的奈奎斯特计算同信噪比换算绑定，有重复扣分风险。此题未进入待审。
- **碰撞检测。** v0.7 生成的原题让 A 在 2,000 m、100 Mbit/s 的简化链路上于 0 μs 开始发送 64 字节，B 在 9.9 μs 开始发送。正确选项是 **A**。单程 10 μs，A 在 5.12 μs 发完，B 的信号于 19.9 μs 到 A，故 A 在本帧发送期间漏检。覆盖最晚返回需要 250 B。原题进入待审，答案独立复算成立。教师解析把“降低发送速率”列作缩短传播时延的办法，发布前应改为“在帧长不变时延长发送时间”。模型审计漏过了这句。[Dordal 的碰撞时序说明](https://intronetworks.cs.luc.edu/current2/ComputerNetworks/ethernet1.html#the-slot-time-and-collisions)
- **局部置换重放。** 同义条件题先把候选范围限定在 P 的帧内，程序复算淘汰 a，Q 访问 b 命中。盲解与审计都确认结果并放行。删去范围限制后，盲解明确给出局部和全局两种解释，后者淘汰 b，故拒绝。这两份题是冻结的外部反例，计入三次验证调用，与从头生成的成绩分开。

原始请求、可见模型输出、用量和评测存放于本地 `.local/question-generation/generalization/v06/paid-v07/`。计算脚本 `paid_oracles.py` 独立于模型。下一阶段优先把可复算结论绑定到学生实际看到的场景，分开记录字段错误、解题错误和审计误判。该轮结果不足以依据通过率选择默认协议，也不支持仅放宽字段检查。最新 408 考纲逐项覆盖和教师盲评仍待完成。

## v0.5 的 DeepSeek high 与 low 对照

沿用原四科请求、材料、v0.5 提示、JSON 模式、120 秒时限和 16,384 token 输出上限。离线拦截正常入口，确认四个作者请求的提示与材料输入逐项匹配原 low 请求。high 每题新跑一次，low 复用已保存结果。两组 API 返回的模型名都为 `deepseek-flash`，low 是历史记录，无法从模型别名确认两批底层服务版本完全一致。该对照覆盖四个任务，每个任务每档一份结果。

| 任务 | low | high 与独立复核 |
| --- | --- | --- |
| 拓扑约束 | 进入待审，题面及答案正确 | 进入待审。枚举五个顶点的全部排列，四个选项对应的拓扑序数量为 2、1、0、2，唯一答案为 B。删去 A→B 再加 B→C 后有两个序列，作者反事实也成立。两档题目均可用 |
| 流水线 | 作者全转发时序错误，流程在盲解阶段挡下 | 作者响应达到 16,384 token 上限，设计字段被截断。离线读取已经完整的学生和教师视图，复算全转发 EX 周期为 3、5、6、7，总计 9 周期。可见题面和主答案能复算，正式题包未完成 |
| 银行家算法 | 进入待审，独立枚举确认原状态只有一条安全序，试探后无安全序 | 作者响应超过 120 秒，未得到完整候选及用量。本例只能比较交付结果 |
| SR 序号回绕 | 材料不足 | 进入待审。核心窗口计算可复算，但 p3 题面直接告知旧 0 已缓存，而评分给这个结论 1 分。独立事件重放发现，自定义 ACK 规则可令发送端停在 0。盲解与审计均未发现 |

在 SR 题的 `N=5` 场景，旧 0 进入接收窗口 `{5,6,7,0,1}`，最终随 5、6、7 再次交付，作者此处正确。`N=4` 时接收窗口为 `{4,5,6,7}`，旧 0 被丢弃且只回 ACK3。发送端缺 ACK0，重传 0 仍只收到 ACK3，`send_base` 无法前移。`2N≤M` 只能说明题设的前后两个窗口不重叠。题目把它称为自定义协议的“最大可用”窗口，却没有区分避免重复和协议仍能前进。

**待审通过均为 2/4，独立复核可直接使用的完整题包为 low 2 份、high 1 份。** high 在同材料下生成了完整的 SR 候选，该候选有审计未发现的缺陷。流水线留下了可复算的主答案，但不能将截断响应算成通过。样本不足以外推全科质量，也不能确定超时是模型推理时间还是服务响应延迟。

用户授权最多 12 次、0.65 美元。本轮实际 **8 次**，6 次有效 JSON，1 次输出截断，1 次超时，失败未重试。有用量的调用共 57,403 输入和 76,775 输出 token，按峰值且不计缓存估算 **0.1094 美元**。超时未返回用量，加入单次最坏预留后，本轮保守上界为 **0.1594 美元**，实际账单可能不同。历史 low 九次有完整用量，峰值同口径估算 0.0847 美元。两轮均按实际尝试数统计。[DeepSeek 官方费率](https://api-docs.deepseek.com/quick_start/pricing/)

实验记录和复算结果位于本地 `.local/question-generation/generalization/v06/paid-high/`，独立脚本为 `v06/high_oracles.py`。实验运行时仍是 v0.5 和用户指定的 high。接续优先让程序从学生可见场景复算关键结果，并将评分泄题、错误解析和传输失败分别处理。

## 题设绑定的离线回归

新增 `public_scenario` 通用命题选项。生成器可选择结构化输入和要问的目标，程序用同一份输入渲染学生题面并复算评分答案。离线使用历史失败场景重放：

| 场景 | 独立复算 | 在通用入口的表现 |
| --- | --- | --- |
| 五级流水线 | ID 最早在 WB 下一周期读到新值时，全转发的 EX 周期为 3、5、7、9、11，最后 WB 为 13。改为同周期写后读，全转发的 EX 周期变为 3、5、6、7、8 | 评分写成旧候选的 10 周期时，在盲解前拒绝。正确值写入现有教师视图的评分点 |
| SR 窗口外回 ACK | 丢 ACK0 后，固定回接收基号减一会回 ACK3，发送基号停在 0，分组 4 发不出。按收到分组的线上序号回 ACK 时，回复 ACK0，基号推进到 4，分组 4 能发出 | 切换 ACK 规则会同时改变可见题面和复算结果。复用旧正确项会被拒绝，修正后进入待审 |
| SR 回绕 | N=5 时重传的旧 0 落入接收窗口，在 5、6、7 后再交付一次 | 可以直接考查交付顺序。小问由目标字段生成，作者无法在小问里插入“旧 0 已缓存”之类提示 |

本轮没有发起新的模型实验。这些回归验证题面、评分值和状态计算的一致性。任意解析文本、知识规则的适用范围及开放作答仍由盲解与审校判断。
