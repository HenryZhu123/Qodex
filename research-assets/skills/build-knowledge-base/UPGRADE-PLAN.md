## 2. 设计决策

### D1 解析：弃用 Tesseract，PDF 统一走 MinerU

- `parse_pdf` 改为 `mineru_parse`：PDF → MinerU → Markdown。
- 删除 `_ocr_page`、`pytesseract` 依赖与 `--ocr` 参数；`requirements.txt` 中的 OCR 注释一并移除。
- PyMuPDF 只保留三个非识别用途：页数统计、分卷切分、MinerU 不可用时的"仅提取文本层"降级（**不再做 OCR**，并在报告里显式标注 `parser=fallback_text_only`）。
- 限流策略：并发 1，失败重试 3 次、指数退避；按 IP 限流错误（`MinerULimitError`）单独处理，退避时间加倍。

### D2 分卷：按 10MB 上限切页段

- 用 PyMuPDF 累计每页字节数，凑到 9MB 就切一卷，写临时 PDF。
- 每卷独立送 MinerU，记录 `page_range`。
- 合并时按卷顺序拼接 Markdown，每卷前插入 `[[PAGES:start-end]]` 标记。
- 验收：117MB 的书能完整解析，卷数与页码区间可核对。

### D3 页码证据：降级但可追溯

MinerU 的 Markdown 不保证页码，因此：

- chunk 的 `page_start/page_end` 由所在卷的页码区间给出（区间近似，不是精确页）。
- `metadata_json` 增加 `page_precision: "volume"`，明确标注精度降级。
- 若 MinerU 输出里出现页分隔标记，则解析并回填精确页码，`page_precision: "page"`。
- 验收：每个 chunk 至少能定位到卷级区间；报告写明精度。

### D4 文本清洗：碎片合并 + 水印剔除

在入库前增加一道 `normalize_blocks`：

1. **碎片判定**：页面内平均行长 < 10 或单字符行占比 > 30% → 判为碎片页。
2. **碎片合并**：碎片页把连续短行按标点（。！？；：）断句合并成段；不跨页合并。
3. **水印剔除**：统计全书行频次，出现次数 ≥ max(5, 页数×0.2) 且长度 ≤ 30 的行判为页眉/页脚水印，全书删除。
4. **换行规范化**：段内单换行转空格，连续空行折叠为一个段落分隔；保留列表、代码块、表格的行结构。
5. **门槛升级**：`empty_line_ratio` / `avg_line_len` 从 warn 升级——碎片页占比 > 50% 直接 fail，要求重解析。

验收（以数据结构 C 语言版为样本，已实测）：

| 指标 | 清洗前 | 清洗后 |
| --- | --- | --- |
| 水印片段占比 | 127/274 = 46.4% | **0** |
| 单字符行占比 | 24.69% | **11.02%** |
| 非空行总数 | 15477 | 3522 |
| 代码行保留（`//for`、`return OK;`、`typedef struct`） | — | **全部保留** |

> 修正记录：初版验收标准写的是"含 5 个以上换行的片段占比降到 <10%"，这个指标是错的——
> 代码块和列表本来就有换行。清洗后该占比为 54%（148/274），属正常。真正的病灶是
> **单字符行**与**跨页水印**，不是换行数量。

实施中修掉的两个 bug（已写入代码注释）：

1. 初版 `normalize_newlines` 把段内换行全合并，导致 C 算法代码被压成一行 → 改为识别
   `looks_structured`（缩进、`{};`、`=<>`、`#define` 等）并保留其换行。
2. 初版水印剔除按"跨页重复 ≥12 次"判定，把 `//for`、`else`、`return OK;` 这些**在每段算法里
   都出现的真代码行**误删 → 收紧为 `is_removable_overlay`：长度 ≤12、不含拉丁字母/数字/
   代码符号、且是中文或纯标点才可删。

### D5 去重：三层阻断

| 层 | 判据 | 触发动作 | 依据字段 |
| --- | --- | --- | --- |
| L1 文件级 | `sha256(原始文件)` 已存在 | 直接阻断，提示已有 `doc_id` 与入库时间 | `documents.source_hash` |
| L2 内容级 | `sha256(规范化全文)` 相同 | 阻断并记为"同内容不同来源"，记录新来源路径 | 新增 `documents.normalized_sha256` |
| L3 片段级 | 逐 chunk 的 `sha256(规范化文本)` 是否已存在 | 已存在则跳过（计 duplicate），不存在则新增 | 新增表 `chunk_registry(chunk_hash PK, doc_id, first_seen_at)` |

- 规范化全文：去空白、去页码/卷标记、全半角统一、小写化，只保留正文语义。
- **修订版识别**：L1/L2 都不命中，但同一 `subject` 下与既有书相似度 ≥ 0.6（用 chunk 集合 Jaccard 估算）→ 判为同书不同版本，允许导入并生成**增量报告**：新增章节、消失章节、改动章节。
- 默认行为 `--on-duplicate skip`；可选 `force`（覆盖）与 `delta`（只入库新增 chunk）。

验收：

- 重复导入同一 PDF → 新增 0 块，退出码 0 并给出提示；
- 导入 Kurose 第 8 版（已有第 7 版）→ 生成增量报告，只新增第 8 版独有段落；
- 同书不同扫描件（L2 命中）→ 阻断，保留来源记录。

### D5 校准结果（2026-11-01 实测）

**纯文本 Jaccard 不可用**。用 12 字 shingle 实测：同科不同书 0.0021、不同科 0.0002，
区分度极低；换成高频二字词集合后同科不同书 0.4668、跨科 0.25，仍与"同书新版"区间重叠。
根因是库里**没有一对两侧都有文本层的同书不同版本**可用于校准（见下）。

**新增关键发现：库中多本教材是纯扫描件，没有文本层。**

| 文件 | 体积 | 可提取正文字符 |
| --- | --- | --- |
| 计算机网络 第7版（严/Kurose 中文） | 111.5MB | 795,973 |
| 计算机网络 第8版（陈鸣译） | 24.1MB | **503（无文本层）** |
| 计算机组成原理第3版（唐朔飞） | 24.3MB | 295,423 |
| 计算机组成原理 学习指导第2版（唐朔飞） | 16.3MB | **0（无文本层）** |
| 数据结构（C语言）严蔚敏 单行本 | 16.4MB | **0（无文本层）** |

这意味着旧流水线遇到这几本只能 fail 或产出空库；**MinerU 不是优化项，是必需品**。
去重检查也必须先判断 `has_text_layer`，无文本层时跳过 L2 直接走 MinerU。

**最终判据：书名 token + 作者 token（双信号），阈值 0.35。**

| 关系 | 书名相似度 | 作者 token 交集 | 判定 |
| --- | ---: | --- | --- |
| Kurose 第7版 vs 第8版 | 0.727 | 有（james/kurose/keith/ross） | `delta_edition` |
| 严蔚敏 单行本 vs 第2版 | 0.389 | 有（严蔚敏） | `delta_edition` |
| 唐朔飞第3版 vs 谭志虎 | 0.429 | 无 | `sibling_book`（同科不同书，允许导入并提示） |
| 数据结构 vs计算机网络 | < 0.15 | 无 | `unrelated` → 新书 |

实现要点：

- **不能只看书名**：0.429（同科不同作者）高于 0.389（同书不同版），单阈值必然误判。
- 作者比对用 token 交集而非字符串全等：`James F. Kurose, Keith W. Ross, 陈鸣` 与
  `James F. Kurose Keith W. Ross` 交集非空即同作者；`唐朔飞` 与 `谭志虎` 交集为空。
- 无文本层时 `content_sha256 = null`，L2 跳过，返回 `needs_mineru: true`。

实测判定（`kb_registry.py check`）：

| 输入 | 判定 |
| --- | --- |
| 已入库的数据结构第2版 PDF | `blocked_L1` |
| Kurose 第8版 | `delta_edition`，`needs_mineru=true` |
| 唐朔飞第3版 | `sibling_book` |
| 严蔚敏单行本 | `delta_edition`，`needs_mineru=true` |

注册表已落盘 `kb_review/registry.sqlite`：4 本已入库书籍、2508 条 chunk 指纹、每本一份术语指纹。

### D1+D2 实施结果（2026-11-01 实测）

**MinerU 有两道硬限制，必须同时满足**：单文件 ≤10MB，且**单文件 ≤20 页**
（`file page count exceeds API limit (20 pages)`）——后者比体积更紧。第 8 版 504 页 / 24.1MB
被切成 **26 卷**（每卷 20 页、0.61–2.9MB），逐卷上传后合并。

`kb_review/books/computer_network_8th/` 实测：

| 指标 | PyMuPDF | MinerU |
| --- | ---: | ---: |
| 可提取正文字符 | **503** | **698,721** |
| 单元数 | 3 | 5,043 |
| 单字符行占比 | — | **0.05%** |
| 水印单元 | — | **0** |
| Markdown 标题 / 表格 | — | 555 / 45 |

耗时约 35 分钟（单卷 35–105 秒），已实现**卷级断点续跑**（每卷 Markdown 落盘，重跑自动跳过）。
结论：扫描件可以救回来；MinerU 输出本身几乎不需要清洗（对比 PyMuPDF 的数据结构书：
24.69% 单字符、127 处水印），D4 清洗保留作兜底。

### D5 双阶段判定（最终设计）

扫描件在入库前没有文本层，算不出文本相似度，因此判定分两阶段：

| 阶段 | 可用信号 | 判据 |
| --- | --- | --- |
| 入库前 | 文件哈希、内容哈希（有文本层时）、书名、作者 | 书名 ≥0.35 且作者 token 有交集 → `delta_edition` |
| 解析后 | 追加"术语指纹"（top-400 二字词 Jaccard） | ≥0.6 → `same_edition`，`evidence=text` |

术语指纹实测：第7版 vs 第8版 top-4000 = 0.8311、top-400 指纹 = **0.6598**；
同科不同书 0.4668；跨科目 0.25。第 8 版入库前判 `delta_edition`（书名 0.727），
解析后仍是 `delta_edition` 且 `evidence=text`（0.6598），两阶段一致。

### D5 阈值校准（2026-11-01 第二轮）

**修正上一轮的设计缺陷**：原提案的"块级覆盖率 ≥0.98"用精确 chunk 哈希计算。但实测
「同内容不同解析」的相似度 0.8913、精确哈希覆盖率却接近 0（OCR 差异让哈希全不相等），
双条件会**恰好漏掉它本该拦下的重复书**。改为**近似重复覆盖率**：3-gram 包含度 ≥0.9
即视为"这块我已看过"。

**修订率 → 相似度曲线**（对第 8 版正文按比例替换，seed=42）：

| 人为修订比例 | top-400 指纹相似度 | 精确哈希覆盖率 |
| ---: | ---: | ---: |
| 0% | 1.0000 | 1.0000 |
| 1% | 0.9512 | 0.9900 |
| 2% | 0.9185 | 0.9806 |
| 5% | 0.8141 | 0.9503 |
| 10% | 0.6949 | 0.9008 |
| 20% | 0.5355 | 0.8012 |
| 30% | 0.4679 | 0.7003 |

曲线说明两件事：

1. **2% 的微修订（0.9185）与同内容重扫（0.8913）几乎重合**，单靠文本指标无法区分"OCR 噪声"
   与"改了两段"。因此不能把"相似度高"直接等同于"重复"。
2. 5% 以上修订会把相似度压到 0.81 以下，0.6 的下限足以覆盖真正的版本差异。

**最终判定顺序（版次元数据优先）**：

| 顺序 | 条件 | 判定 |
| --- | --- | --- |
| 1 | 两侧版次号可解析且不同（第7版 vs 第8版） | `delta_edition`，`evidence=edition-number` |
| 2 | 指纹 ≥0.85 **且** 近似重复覆盖率 ≥0.98 | `rejected_duplicate` |
| 3 | 指纹 ≥0.85 但覆盖率 <0.98 | `delta_edition`（小幅修订） |
| 4 | 0.6 ≤ 指纹 < 0.85 | `delta_edition` |
| 5 | 指纹 <0.6 且书名/作者不匹配 | `new_book` |
| 6 | 书名相似但作者不同 | `sibling_book` |

锚点数据（同一生产指标 top-400 指纹）：

| 关系 | 相似度 | 期望判定 |
| --- | ---: | --- |
| 同内容不同解析 | 0.8913 | `rejected_duplicate` |
| Kurose 第7版 vs 第8版 | 0.6598 | `delta_edition`（版次不同） |
| 同科不同书（唐朔飞 vs 谭志虎） | 0.4668 | `new_book` / `sibling_book` |
| 跨科目 | 0.25 | `new_book` |

第 8 版实测：入库前与解析后均为 `delta_edition`，`evidence=edition-number`（8 vs 7）。
近似重复覆盖率实测：第 8 版前 120 个单元对第 7 版覆盖 **0.325**（不同译本措辞差异大），
自比对 0.975，符合预期。

**增量产物形态（用户确认）**：增量块**单独成文件**，不并入现有 `kb.sqlite`，便于回滚；
文件内保留 `doc_id`、来源路径与 `first_seen_at`。

## 2.5 方案修正（2026-11-01，用户裁定）

**原 D5 被取代。** 之前的"重复→拒绝、相似→增量、其余→新书"是**文件级**二元判断，只回答
"这本书要不要再导一遍"，回答不了"两本书的内容该怎么共存"。

现行方案改为**内容级四类关系**，已写入 skill：

- 规则文档：`references/knowledge-relations.md`
- 主流程：`SKILL.md` 第 7 条非约束规则 + `Phase 6 — multi-source alignment`
- 完成判定新增第 7 条：多来源场景下每个候选对必须有关系标签，冲突必须人工复核

| 关系 | 处理 | 关键字段 |
| --- | --- | --- |
| `equivalent` | 只留一份 canonical，另一份记入来源 | `canonical_id`、`source_versions`、`aliases` |
| `exclusive` | 各自保留，打来源标签 | `source`、`scope`、`effective_*` |
| `conflict` | 两份都留，显式标注，禁止合并 | `conflict_group_id`、`conflict_stance` |
| `complementary` | 两份都留，建立关联 | `related_to` |

判定顺序固定：**先冲突，再等价，最后独有/互补**。若先按相似度合并，会把"同一问题不同答案"
误当重复抹平——这是最坏的结果。

原 D5 的三层哈希与阈值校准仍然有效，但降级为**候选生成与快速路径**：

- L1/L2 文件哈希命中 → 不重复解析，但**仍要**在 `source_versions` 登记新来源；
- 术语指纹（0.6/0.85）与近似重复覆盖率（≥0.98）用于**筛选候选对**，不再直接决定"拒绝入库"；
- 版次号（第7版/第8版）作为强先验：版次不同时，高度相似的内容更可能是 `equivalent` 而非重复；
- 修订率曲线仍是判断"相似度到什么程度还可能是同一段内容"的依据。

**增量产物形态**：单独文件 `delta/<doc_id>.jsonl` + 关系统计报告，不并入现有 `kb.sqlite`，
保证可回滚。
