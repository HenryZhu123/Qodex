# 知识关系与合并规则

多来源知识入库时的统一规则。适用于同一科目的多本教材、同一本书的不同版次、
题库与教材、讲义与真题解析等一切"同一领域出现两份来源"的场景。

本规则是**内容级**的，取代"重复就拒绝入库"的二元判断：一本书是否入库不取决于它像不像旧书，
而取决于**逐块内容**与既有内容构成哪种关系。

## 1. 四类关系

对任意两个来源 A、B 的任意两个知识块，判定为且仅判定为以下之一：

| 关系 | 含义 | 处理 |
| --- | --- | --- |
| `equivalent` | 表述相同或语义等价 | 只保留一份，合并来源记录 |
| `exclusive` | 仅 A 有或仅 B 有 | 各自保留，打来源标签 |
| `conflict` | 同一问题给出不同答案 | 两份都保留，显式标注冲突 |
| `complementary` | 不重复但相关（A 讲流程、B 讲例外） | 两份都保留，建立关联 |

判定顺序固定为：**先判冲突，再判等价，最后判独有/互补**。理由：等价与冲突在字面上都可能
高度相似（同样的术语、同样的句式），若先按相似度合并，会把冲突误当成重复抹平——这是最不
可接受的错误。

## 2. `equivalent`：交集

### 规则

- 只入库一份，称为 canonical 表述。
- 另一份的**来源**记入 `source_versions`，不丢来源。
- 若两份表述不同但等价，选一份更规范的作为 canonical，另一份的表述记为 `aliases`。

### canonical 选择顺序

1. 版次更新者优先（第 8 版优于第 7 版）；
2. 主教材优先于辅导书、讲义、课件；
3. 表述更完整、含定义与边界的优先；
4. 若仍无法区分，取首次入库者，并在 `canonical_note` 写明"随机并列"。

选择理由必须写入 `canonical_note`，便于日后复核。

### 禁止

- 不得因为来源不同就各存一份（检索会重复召回同一事实）。
- 不得因为 canonical 是新版就删除旧版来源记录。

## 3. `exclusive`：A 独有 / B 独有

### 规则

- 全部保留，不得丢弃。
- 每块打 `source` 标签，必要时补 `scope`（适用范围）、`effective_from` / `effective_to`。

### 判定边界

- 只在 A 出现的章节、例子、习题，属 `exclusive`。
- 同一知识点在 B 中被重写但结论一致，属 `equivalent`，不是 `exclusive`。
- 旧版有、新版删掉的内容：仍保留，标 `effective_to`（该版次起失效），因为真题可能考旧口径。

## 4. `conflict`：冲突

这是最危险的一类，处理不当会让模型把两种说法混成一句，产出既不符合 A 也不符合 B 的答案。

### 什么算冲突

同时满足三条：

1. 指向**同一问题或同一对象**；
2. 给出**互不相容的结论**（数值、公式、判定规则、适用条件相反）；
3. 不是单纯的详略差异或口径差异。

### 什么不算冲突

- 一个讲一般情况、一个讲例外 → `complementary`；
- 单位、符号、排版不同但数值一致 → `equivalent`；
- 不同版本适用不同考试大纲 → 记为 `scope` 差异，不是冲突，但要在元数据中写明适用范围；
- 一方明显是笔误且可判定 → 修正后按 `equivalent` 处理，并在 `canonical_note` 记录修正依据。

### 处理

- 两份**都保留**，各自打 `source`。
- 同一冲突事件共享一个 `conflict_group_id`。
- 每份注明 `conflict_stance`（如 `A=8mm, B=6mm`）与 `conflict_reason`（争议点在哪）。
- **禁止**自动择一、禁止把两份合成一句新表述。

### 检索时

- 若召回结果中含同一 `conflict_group_id` 的多条，必须**全部返回**，不得只返回相似度最高的一条。
- 组装给模型的上下文时，按来源分别标注，例如：

```text
[来源 A：教材第8版 p.211] 拥塞窗口按 8mm 计算……
[来源 B：教材第7版 p.198] 拥塞窗口按 6mm 计算……
注意：两条来源对同一参数给出不同取值，请依据来源版本或题目适用范围作答，不要合并表述。
```

- 检索层不得自行决定哪一方正确；是否采信由模型结合题目与来源信息判断，或交由人工。

## 5. `complementary`：互补

### 规则

- 两份都保留。
- 在双方元数据中写 `related_to`（对端 `chunk_id` 或 `canonical_id`）。
- 检索时可一并召回：命中 A 时把 `related_to` 的目标作为扩展上下文（默认开启，可按需关闭）。

### 判定边界

- A 给出算法流程、B 给出异常处理 → 互补；
- A 给出定义、B 给出证明 → 互补；
- A 与 B 只是同一段落的两种排版 → `equivalent`。

## 6. 元数据字段

每块至少具备：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `chunk_id` | 是 | 全局唯一 |
| `canonical_id` | 是 | 知识单元标识；`equivalent` 合并后的共同标识 |
| `source` | 是 | 本块来源标识（如 `kurose8`） |
| `source_versions` | 是 | 该 `canonical_id` 覆盖的全部来源 |
| `relation` | 是 | `canonical` / `alias` / `exclusive` / `conflict` / `complementary` |
| `aliases` | 否 | 等价但非 canonical 的表述 |
| `scope` | 否 | 适用范围（章节、考试大纲、机型等） |
| `effective_from` / `effective_to` | 否 | 生效/失效的版次或年份 |
| `conflict_group_id` | 冲突时必填 | 同一冲突的共享标识 |
| `conflict_stance` | 冲突时必填 | 本方主张 |
| `related_to` | 互补时必填 | 关联块标识列表 |
| `canonical_note` | 合并时必填 | canonical 选择或修正理由 |

## 7. 判定流程

1. **候选生成**（确定性、便宜）：同一科目内，按术语指纹与 3-gram 重叠筛出高相似块对，
   召回率优先，宁多勿漏。
2. **关系判定**（语义 Judge）：对候选对输出四选一 + 理由，冲突必须先判。
3. **冲突复核**（人工）：所有 `conflict` 进入人工队列，因为误判代价最高。
4. **写入**：按关系更新 `canonical_id` / `source_versions` / 冲突组与关联。
5. **可回滚**：每次合并写一条变更记录（来源、关系、理由、时间），支持按来源撤销。

## 8. 与文件级去重的关系

文件级哈希（同文件、同内容哈希）仍保留，仅作为**快速路径**：

- 命中文件哈希 → 不重复解析，但**仍要**在 `source_versions` 中登记该来源；
- 不得因为"整本书重复"就跳过内容级关系判定——部分重复的书（修订版）必须逐块判定。

## 9. 验收样例

| 场景 | 期望结果 |
| --- | --- |
| 同一本书重扫一遍 | 全部 `equivalent`，新增块 0，`source_versions` 增加一项 |
| 第 7 版 vs 第 8 版 | 共同章节 `equivalent`、新版新增 `exclusive`、口径变化处 `conflict` |
| 教材 vs 习题解析 | 大部分 `complementary`，少数 `exclusive` |
| 两本书同一公式给出不同系数 | `conflict`，两份保留且共享 `conflict_group_id` |
| 一份讲一般情形、一份讲例外 | `complementary` + `related_to` |
