# build-knowledge-base 技能评估说明

本文回答四个问题：

1. 评估这个技能需要准备什么？
2. 测试集要多少文件才够用？
3. 主要看哪些指标？
4. 指标达到多少算合格、多少算优秀？

---

## 1. 评估需要准备什么

### 1.1 软件环境

| 项 | 要求 |
|---|---|
| Python | 3.10+ |
| 依赖 | `pip install -r requirements.txt`（PyMuPDF、python-docx 或 docx2txt、charset-normalizer、BeautifulSoup、lxml、jieba） |
| OCR（可选） | `pytesseract` + Tesseract 二进制 + `chi_sim`/`eng` 语言包 |
| DOC（可选） | LibreOffice（`soffice`）或 Microsoft Word |
| 数据库 | 无需外部服务，SQLite 随 Python 自带 |

### 1.2 测试语料

需要覆盖三类输入：

1. **干净文本**：TXT / MD，UTF-8，结构与正文完整；
2. **结构化文档**：DOCX（含标题样式、表格）、HTML；
3. **PDF**：至少包含文字型 PDF、带页眉页脚/竖排侧边栏的 PDF、扫描型 PDF 三种。

建议来源：

- 你自己已有的 4 本教材（`source/`）；
- 公开的考研真题 PDF；
- 人为构造的边界样本（乱码、空文件、超长文件、加密 PDF）。

### 1.3 标注答案（Ground Truth）

每个测试文档至少需要：

| 标注项 | 说明 | 是否必需 |
|---|---|---|
| **文档类型** | **txt / docx / pdf / html** | **必需** |
| **是否为扫描件** | **是 / 否** | **必需** |
| **是否应被跳过** | **例如封面、无正文文件** | **必需** |
| **期望分块模式** | **hierarchical / paragraph / question / code** | **必需** |
| 期望章节数 | PDF 的章数，或 DOCX 的标题数 | 推荐 |
| **关键术语表** | **每个文档挑 5–10 个必须能检出的术语** | **必需** |
| 术语所在位置 | 章节 / 页码，用于判断锚点是否正确 | 推荐 |

### 1.4 检索查询集（Retrieval Queries）

这是评估 RAG 质量的核心。每条查询需要：

```json
{
  "query_id": "q001",
  "doc_id": "d001",
  "query": "银行家算法的四个数据结构是什么",
  "gold_chunk_ids": ["d001:00167"],
  "gold_heading": "3.7.2 利用银行家算法避免死锁",
  "gold_pages": [121],
  "query_type": "definition"
}
```

`query_type` 建议分为：

- `definition`：术语定义
- `procedure`：步骤/流程
- `comparison`：概念辨析
- `formula`：公式/计算
- `question`：题目相关
- `unanswerable`：文档里没有答案（用于测“无证据”能力）

### 1.5 人工核对材料

需要人工或 LLM 辅助核对以下内容：

- 抽样文本是否乱码；
- 分块是否切断句子/公式/题目；
- 检索结果是否真的相关；
- 生成的 chunk 是否包含错误拼接。

### 1.6 环境隔离

- 每次评估使用独立的 run 目录；
- 记录 `run_id`、`seed`、依赖版本；
- 不要用评估语料反向调参后再报同一个测试集结果。

## 2. 测试集要多少文件才够用

评估目标不同，所需规模不同。

### 2.1 按评估目标推荐规模

| 评估目标 | 文档数 | 查询数 | 说明 |
|---|---:|---:|---|
| 冒烟测试（能跑通） | 2–5 | 5–10 | 只验证流程，不报指标 |
| 功能覆盖（每类格式都跑到） | 8–12 | 30–50 | 每种格式至少 2 个，含 1 个失败样本 |
| 可信评估（可写进报告） | 20–30 | 100–150 | 每类格式至少 5 个，含边界样本 |
| 学术级评估（可写进论文） | 50–100 | 300–500 | 每类格式 10+，含跨学科、跨语言 |

### 2.2 按输入类型的配额

| 类型 | 最小 | 推荐 | 备注 |
|---|---:|---:|---|
| TXT / MD | 3 | 10 | 含 1 个 GB18030 编码样本 |
| DOCX | 3 | 10 | 含 1 个只有 `docx2txt` 可用的样本 |
| HTML | 2 | 5 | |
| 文字型 PDF | 5 | 20 | 含页眉页脚、竖排侧栏 |
| 扫描型 PDF | 2 | 5 | 测 OCR 分支 |
| 异常样本 | 3 | 8 | 乱码、空文件、加密、超大文件 |

### 2.3 规模下限判断

可以这样判断“够不够”：

- **文档维度**：每类格式至少 5 个，否则该类要么漏掉某个分支（例如只有 PDF 走不到 DOCX 分支），要么指标方差太大。
- **查询维度**：每个文档至少 5 条查询，总查询数不少于 **100**，否则 Recall@5 的置信区间会很宽。
- **失败样本**：至少保留 3 个已知会 `fail` 的样本，用来验证门禁确实生效。

> 结论：**可写进报告的最小规模是 20 个文档 + 100 条查询；比较稳妥的规模是 50 个文档 + 300 条查询。**

## 3. 评估指标

分为五层，从解析质量到检索质量，再到端到端可用性。

### 3.1 解析层（Parsing）

| 指标 | 定义 | 怎么算 |
|---|---|---|
| 解析成功率 | 成功解析的文档数 / 总文档数 | 失败包括抛异常、0 字符、报错退出的情况 |
| 字符保留率 | 解析后字符数 / 原文估计字符数 | 原文估计可用 PDF 页数 × 平均字数，或用人工抽样 |
| 编码正确率 | 无乱码字符的文档数 / 总文档数 | 检查 `�`、`锟斤拷` 等 |
| 格式分支覆盖率 | 实际走到的解析分支数 / 支持的分支数 | 分支包括 txt / docx / doc / pdf / html / ocr |
| 警告可解释率 | 有 warning 的文档中，warning 与实际问题的吻合比例 | 人工抽样 |

### 3.2 完整性抽样层（Integrity）

| 指标 | 定义 | 怎么算 |
|---|---|---|
| 抽样覆盖率 | 实际抽样单元数 / 理论 10% 单元数 | 看 `ratio_actual` |
| 抽样可复现率 | 同 seed 重跑得到相同样本的比例 | 应为 100% |
| 门禁准确率 | 被判 `fail` 的样本中确实应被拒绝的比例 | 人工判定 |
| 门禁召回率 | 应被拒绝的样本中被判 `fail` 的比例 | 人工判定 |
| 指标触发一致性 | 同一份文本多次抽样 verdict 一致的比例 | 反映抽样方差 |

### 3.3 分块层（Chunking）

| 指标 | 定义 | 怎么算 |
|---|---|---|
| 分块模式准确率 | 自动选中的 mode 与标注 mode 一致的比例 | 核心指标 |
| 标题路径覆盖率 | 有 `heading_path` 的 chunk 比例 | 教材类应接近 100% |
| 页码锚点覆盖率 | 有 `page_start/page_end` 的 chunk 比例 | PDF 应接近 100% |
| 句子截断率 | 被切断的句子数 / 总句子数 | 人工抽样 100 个 chunk |
| 空块率 | 空 chunk 数 / 总 chunk 数 | 应为 0 |
| 纯标题块率 | 只有标题的 chunk 数 / 总 chunk 数 | 应为 0 |
| 重复块率 | 重复 `content_hash` 数 / 总 chunk 数 | 越低越好 |
| 尺寸合格率 | 落在 `[min_chars, max_chars]` 内的 chunk 比例 | 反映尺寸策略是否合适 |

### 3.4 检索层（Retrieval）

| 指标 | 定义 | 参考值 |
|---|---|---|
| Recall@5 | 前 5 条中至少命中 1 个 gold chunk 的查询比例 | 核心指标 |
| Recall@10 | 前 10 条中至少命中 1 个 gold chunk 的查询比例 | |
| MRR | 第一个相关结果排名的倒数均值 | |
| Hit Rate@1 | 第一条就是相关结果的比例 | |
| 无答案拒答率 | `unanswerable` 查询中返回空结果的比例 | 防止幻觉 |

### 3.5 端到端可用性

| 指标 | 定义 |
|---|---|
| 一次跑通率 | 无需人工干预即可完成 plan → ingest 的比例 |
| 人工干预次数 | 每次 run 需要人工改配置/改代码的次数 |
| 重复 ingest 一致性 | 重复执行后 documents/chunks 数不变 |
| 耗时 | 每 100 页 PDF 的处理时间 |
| 可复现性 | 同输入同 seed 两次结果一致 |

## 4. 数值门槛

以下分“合格”和“优秀”两档。假设测试集达到 **20 文档 + 100 查询** 的可信规模。

### 4.1 解析层

| 指标 | 合格 | 优秀 |
|---|---:|---:|
| 解析成功率 | ≥ 90% | ≥ 98% |
| 编码正确率 | ≥ 95% | 100% |
| 格式分支覆盖率 | ≥ 80% | 100% |
| 字符保留率 | ≥ 85% | ≥ 95% |

### 4.2 完整性抽样层

| 指标 | 合格 | 优秀 |
|---|---:|---:|
| 抽样覆盖率 | 8%–12% | 9.5%–10.5% |
| 抽样可复现率 | 100% | 100% |
| 门禁准确率 | ≥ 80% | ≥ 95% |
| 门禁召回率 | ≥ 80% | ≥ 95% |

### 4.3 分块层

| 指标 | 合格 | 优秀 |
|---|---:|---:|
| 分块模式准确率 | ≥ 75% | ≥ 90% |
| 标题路径覆盖率（教材） | ≥ 80% | ≥ 95% |
| 页码锚点覆盖率（PDF） | ≥ 90% | 100% |
| 句子截断率 | ≤ 10% | ≤ 3% |
| 空块率 / 纯标题块率 | 0% | 0% |
| 重复块率 | ≤ 5% | ≤ 1% |
| 尺寸合格率 | ≥ 85% | ≥ 95% |

### 4.4 检索层

| 指标 | 合格 | 优秀 |
|---|---:|---:|
| Recall@5 | ≥ 0.70 | ≥ 0.85 |
| Recall@10 | ≥ 0.80 | ≥ 0.90 |
| MRR | ≥ 0.55 | ≥ 0.75 |
| Hit Rate@1 | ≥ 0.50 | ≥ 0.70 |
| 无答案拒答率 | ≥ 0.70 | ≥ 0.90 |

### 4.5 端到端

| 指标 | 合格 | 优秀 |
|---|---:|---:|
| 一次跑通率 | ≥ 80% | ≥ 95% |
| 人工干预次数 | ≤ 1 次/run | 0 次/run |
| 重复 ingest 一致性 | 100% | 100% |
| 每 100 页 PDF 耗时 | ≤ 5 分钟 | ≤ 2 分钟 |
| 可复现性 | 100% | 100% |

## 5. 评估流程

1. **准备语料与标注**：按第 1–2 节准备文档、查询集和标注文件。
2. **冻结版本**：记录 commit、依赖版本、seed。
3. **跑流水线**：对每个文档执行 `run --stop-after ingest`。
4. **自动采集**：从 `parsed/`、`integrity_report.md`、`chunk_plan.md`、`chunk_report.md`、`verification_report.md` 中读指标。
5. **人工抽样**：抽查 50–100 个 chunk，核对截断、乱码、锚点。
6. **检索评估**：用查询集跑 `query`，计算 Recall@5、MRR、拒答率。
7. **汇总成表**：按第 4 节门槛判定合格/优秀。
8. **消融**：至少做三组——关闭 10% 门禁、强制 `paragraph` 模式、关闭 TOC 前置页过滤——观察指标变化。

---

## 6. 必须做的消融

| 消融项 | 做法 | 观察指标 |
|---|---|---|
| 关闭完整性门禁 | 跳过 sample，直接 chunk | 乱码 chunk 比例、检索准确率下降幅度 |
| 关闭分块模式选择 | 全部用 `paragraph` | Recall@5 下降幅度 |
| 关闭标题路径 | chunk 不带 `heading_path` | 检索准确率、可解释性 |
| 关闭页码锚点 | 去掉 `[[PAGE:n]]` | 证据可定位性 |
| 关闭 TOC 前置过滤 | 保留封面/前言 | 噪声 chunk 比例 |

## 8. 常见坑

1. **只测成功样本**：不测乱码/空文件，会高估门禁能力。
2. **查询集来自文档原文**：直接把原文句子当查询，会虚高 Recall；应改写后提问。
3. **样本太少**：少于 20 文档时，单篇失败就会让成功率波动 5% 以上。
4. **不冻结版本**：改了切块规则再报旧结果，不可复现。
5. **只报平均值**：要同时报最差文档的表现，避免被平均数掩盖。
6. **忽略锚点**：只看 Recall 不看 page/heading 是否正确，会导致“能查到但引不对”。
