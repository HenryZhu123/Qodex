# 知识库有效性消融实验设计

目的：验证"多来源知识库 + 等价去重 + 冲突显式标注"这套装配方式**是否真的提升审校质量**，
并分离出提升究竟来自"内容更多"还是"冲突被显式标注"。

## 1. 处理臂

唯一变量是知识库的装配方式，其余全部冻结（reviewer 模型、prompt、并发、数据集、judge）。

| 臂 | 知识库装配 | 想回答的问题 |
| --- | --- | --- |
| `A0` | 关闭知识库（`logic_check` 不带证据） | 没有库时基线是多少 |
| `A1` | 单源：仅第 7 版 `kb.sqlite`（现状生产） | 单源库值多少 |
| `A2` | 多源：7 版 + 8 版 186 块，等价块去重，冲突组返回双侧 + 警示 | 新方案是否更好 |
| `A3` | 多源但**不展开冲突**（只返回排名最高的一侧，无警示句） | "冲突标注"本身贡献多少 |
| `A4`（可选） | 多源但**索引包含等价块**（重复召回） | "等价去重"是否必要 |

`A3` 是这组实验的关键：它和 `A2` 的差别只有一条——要不要把对侧的冲突内容返回并标注。
若 `A2 > A3`，说明收益来自冲突处理；若 `A2 ≈ A3`，说明收益只来自内容变多。

## 2. 样本

优先全量 318 条，四臂约 4 × 1.5 小时。

预算受限时用分层子集，但必须满足：

- **KB 相关组**：对每题用题干 + 选项做一次 KB 检索，保留命中冲突组、或只命中 8 版独有块的题
  （预计 30–60 题）；
- **对照组**：同科目同标签分布随机抽等量题；
- 两组都要跑，只跑相关组会把效应量高估。

## 3. 指标

主指标（Prediction 级，评估协议 v1.0.0）：Precision、Recall、F1。

关键诊断指标：

| 指标 | 定义 | 为什么需要 |
| --- | --- | --- |
| **冲突题准确率** | 涉及冲突组的题上，模型是否采用正确来源、未把两种说法混写 | 这是本方案的核心卖点 |
| 证据引用率 | 输出是否真的引用了召回证据（人工抽检 30 条） | 排除"奖励来自更长上下文" |
| 上下文成本 | 平均证据 token、检索延迟 | 冲突扩组会更贵，必须算进去 |
| 无错题 FPR | 多源可能引入干扰，导致误报上升 | 防止"召回涨了、误报也涨" |
| 未命中率 | 检索 top-k 里没有相关块的题占比 | 区分"库没用上"与"库用了没用" |

## 4. 预注册判读标准

实验前先写死，避免事后挑指标：

1. `A2` 相对 `A1` 的 F1 提升 **≥ 3pp** 且冲突题准确率提升 → 方案有效；
2. `A2` 优于 `A1` 但上下文成本上升超过 50% → 需要权衡，不能直接判定有效；
3. `A2 > A3` → 冲突标注本身有价值；`A2 ≈ A3` → 价值只来自内容量；
4. `A2 < A1` → 多源引入噪声，先查候选生成与合并策略，不要改阈值糊过去；
5. `A4 < A2` → 等价去重是必要的，可写进规范。

## 5. 统计与偏差控制

- **配对比较**：同一道题在不同臂之间的判定差异用 McNemar 检验，比对比两个边际率灵敏得多。
  318 条时单臂 F1 的 95% CI 约 ±5pp，3pp 的差异**不能**靠边际率判定。
- **同期交错**：各臂在同一天内交错跑，避免上游模型漂移（此前已实测到 TalkWeb 在计费日切换时
  行为突变）。
- **盲评**：judge 不知道样本属于哪一臂；judge 固定为 `glm-5.3`，与臂无关。
- **人工抽检**：每臂随机 30 条人工核验，估计 judge 的错判率。
- **冲突题单独报告**：冲突组只有 25 个，样本少、置信区间宽，结论必须单独列出，不能混进总分。

## 6. 实施所需改动

1. `KnowledgeBaseRetriever` 已支持多库与冲突展开（本轮已完成）；还需一个开关：
   `EXAM_CHECKER_KB_MODE = off | single | multi | multi_noconflict | multi_with_dupes`。
2. `run_end_to_end_evaluation.py` 增加 `--kb-mode`，把开关透传；输出目录按臂区分
   （`ablation/a0`…`a4`）。
3. 每臂用同一份 `results.jsonl` 流程评分，复用 `protocol_eval/evaluate_protocol.py`。
4. 汇总脚本输出：各臂 P/R/F1、冲突题准确率、上下文 token、延迟、配对 McNemar p 值。

## 7. 预期与风险

- 预期效应不大：知识库只作用于 8 个任务中的 `logic_check`，且大多数题不依赖教材细节。
  因此**不要**期待 F1 大涨；如果涨了 10pp，优先怀疑泄漏或 judge 偏差。
- 冲突组只有 25 个，冲突题准确率的结论只能是方向性的。
- 若 `A0 ≈ A1`，说明当前知识库对审校几乎无贡献，应优先修检索召回，而不是继续加书。
