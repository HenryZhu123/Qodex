# Review taxonomy v2

This directory is generated by `scripts/migrate_solvability_taxonomy.py`. Source datasets are immutable and remain in their original directories.

## Taxonomy decision

The legacy top-level labels `missing_info` and `unsolvable` are merged into:

- `error_type`: `solvability_failure`
- production Chinese label: `可解性错误`
- required `solvability_subtype`: one of `missing_required_condition`, `underspecified_task`, `no_valid_answer`, `multiple_valid_answers`, `contradictory_conditions`, or `indeterminate_answer`

`legacy_error_type` and `legacy_error_detailed_type` preserve provenance. They are not training targets.

## Dataset variants

Each dataset directory contains aligned CSV, full JSONL, and gold JSONL files, plus:

- `migration_manifest.jsonl`: row-level label/adjudication trace.
- `summary.json`: before/after counts.
- `strict/`: rows eligible for strict headline metrics.

For Dev A and Dev B, the main and strict variants are identical apart from the new taxonomy fields. For Blind v2, the main variant applies human removals but keeps diagnostic rows and human-kept weak leakage rows with `strict_eval_eligible=false`; `strict/` excludes them.

## Manual adjudication policy

- A blank decision with both a corrected category and a written reason is recorded as an inferred `keep`, with `human_decision_inferred=true`.
- `remove` rows are absent from the adjudicated and strict datasets but remain in the migration manifest.
- `diagnostic_only`, L0 leakage, and L1 leakage remain traceable but are excluded from strict metrics.
- Human judgments are never silently replaced by the quality policy; `human_decision` and `strict_eval_eligible` are separate fields.

Regenerate from the repository root with:

```powershell
python research-assets/review_eval/scripts/migrate_solvability_taxonomy.py
```
