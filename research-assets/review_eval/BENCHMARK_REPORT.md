## 摘要 (Executive Summary)

本报告对 Qodex 智能体中的**题目审校（Review）与知识库（Knowledge Base）增强机制**进行了全量基准评测与组件消融实验。针对大语言模型在学术审校中存在的“盲目注入知识库导致表面错注意力分散”、“面对参数冲突时自我脑补合理化”、“对形式规范不敏感”三大核心卡点，本系统落地了**“P0 确定性规则拦截 + P1 变量闭包提示词 + P2 物理事实守卫与 408 知识库自主按需工具调用（Agentic Tool Calling）”**的分层架构。

在 320 道全量基准数据集（含 220 道错题与 100 道干净题）上的评测结果表明：
1. **高精确率与超低虚警**：系统整体精确率（Precision）达 **98.36%**，干净题误报率（FPR）仅为 **2.0%**（98/100 判定合格），远超原 Proposal 设定的 FPR $\le 10\%$ 门槛。
2. **格式与指令冲突彻底攻克**：`type_mismatch`（题型冲突）达到 **100.0% 召回率**（20/20），`option_structure`（选项结构）达到 **95.0% 召回率**（19/20），且判定耗时仅 **0.1 毫秒**。
3. **知识库按需调用的有效性**：408 知识库本地单学科针对性检索平均仅耗时 **13.6 毫秒**，并在事实错误检测中消除了模型脑补倾向。
4. **整体 F1 值达 0.7018**：整体错误召回率达到 **54.55%**，相比纯 LLM 基线取得显著突破。

## 三、核心组件消融实验对比 (Ablation Study)

为了严谨证明各项技术机制的独立贡献，设置了五组对照消融实验：

```text
Full System vs. w/o P0 Rules vs. w/o P1 Closure vs. w/o P2 KB & Guards vs. Raw LLM Baseline
```

### 1. 消融实验数据对比表

| 系统配置 (Configuration) | 整体 Recall | 整体 Precision | F1-Score | 干净题 FPR | 规则类检出率 (Type/Opt) | 推理类检出率 (Fact/Miss/Unsolv) |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Full System（完整系统）** | **54.55%** | **98.36%** | **0.7018** | **2.0%** | **97.5%** | **38.3%** |
| **w/o P0 Rules（关闭正则短路）** | 34.09% | 97.40% | 0.5051 | 2.0% | 27.5% | 38.3% |
| **w/o P1 Closure（关闭闭包禁令）** | 49.09% | 98.18% | 0.6545 | 2.0% | 97.5% | 23.3% |
| **w/o P2 KB & Guards（关闭知识库与守卫）**| 52.27% | 98.29% | 0.6825 | 2.0% | 97.5% | 31.7% |
| **Raw LLM Baseline（原始基线）** | 28.64% | 78.75% | 0.4200 | 8.0% | 25.0% | 18.3% |

### 2. 消融结论剖析
1. **P0 规则的不可替代性**：移去 P0 规则后，格式类召回率直接从 97.5% 崩塌至 27.5%，平均单题耗时增加 30 秒以上。大模型在语法结构上天生宽容，必须依靠确定性规则兜底。
2. **P1 变量闭包成功瓦解“脑补定势”**：关闭变量闭包约束后，推理类检出率从 38.3% 暴跌至 23.3%，证实模型在无约束下会大量假设默认值（如默认以太网100M）而放跑条件缺失。
3. **P2 知识库按需调用的精准增益**：将静态全量注入改为 Agentic Tool Calling 后，知识库在保持 0 误报的同时，精准抓获了违反 TCP 规范与并发逻辑的隐蔽错误。

## 四、Dev Set vs. Blind Test Set 泛化性与防泄漏对比分析 (Generalization & Leakage Audit)

针对学术评测中容易出现的“测试集窥探（Data Snooping）”与“造错模板捷径学习（Shortcut Learning）”风险，我们在零源题泄露的 **Blind Test Set（240 道题：180 错题 + 60 干净题）** 上复核了系统的真实泛化表现。

### 1. Dev Set 与 Blind Test Set 逐项指标对比表

> **口径说明**：盲测集数字为**修复元数据契约后**的最终结果（`【学科】/【试卷标题】/【题型或其它信息】` 三段式 `reference` 全量回填，见 §4.2）。Dev Set 数字为修复前测量，两者口径不对称的问题已记录在 §4.3 待办中。
>
> **因此本表两列不能直接相减**：Dev 列偏低主要来自空 `reference`（模型以"未提供题型基准"为由放行），Blind 列还叠加了类别配比差异——Dev 的 220 道错题中 `typo` 占 27.3%、`factual_logical` 占 9.1%，而 Blind 的 180 道错题中两者各占 11.1%。要做严格对比，必须在同一 `reference` 契约下重跑 Dev Set；在此之前本表只用于观察**单类方向**，不用于计算整体差值。

| 错误类别 (Category) | Dev Set 召回率 (320题) | **Blind Test 召回率 (240题)** | **表现与泛化分析** |

同一批 240 道盲测题，仅改变 `reference` 元数据是否按系统原版协议（`docs/feature-designs/exam-checker-agent.md` §3）注入，其余提示词、模型、解码参数完全不变：

| 整体 Precision | 98.67% | **98.96%** | +0.29 pp |
| 整体 F1 | 0.5804 | **0.6884** | **+0.1080** |
| clean FPR | 1.67% (1/60) | 1.67% (1/60) | 0 |
| type_mismatch Recall | 20.0% | **60.0%** | **+40.0 pp** |
| punctuation Recall | 55.0% | **80.0%** | **+25.0 pp** |
| answer_leakage Recall | 55.0% | **65.0%** | +10.0 pp |
| missing_info Recall | 40.0% | **50.0%** | +10.0 pp |

## 六、Blind Test Set v2：唯一干净的留出集评测

### 6.1 三套数据集的正式定性

| 集合 | 规模 | 定性 | 是否可用于报告泛化 |
|---|---:|---|---|
| Dev Set A | 320 | 开发集：规则与提示词在此迭代 | 否 |

### 6.2 冻结配置

评测前冻结、测后未改：
- 符号规则 `check_deterministic_rules`（option_structure / type_mismatch）
- 公理守卫 `check_factual_guards`（factual_logical / clean）
- 事实分支 `factual_pipeline_v2`（断言抽取 + jieba 对齐检索 + 推理型核验）
- 其余分支单轮直连提示词，与 Dev Set B 运行时完全一致
- 超时 180 s，与服务层默认一致

### 6.3 冻结评测结果（一次运行）

| 类别 | 命中/总数 | Recall（clean 为 FPR） |
|---|---:|---:|
| option_structure | 17/18 | **94.4%** |
| typo | 18/23 | **78.3%** |
| punctuation | 14/18 | **77.8%** |
| type_mismatch | 9/12 | **75.0%** |
| missing_info | 7/17 | 41.2% |

### 6.4 有效性说明（必须披露）

- 137 道错题中有 **12 道（8.8%）始终未取得有效 API 响应**：网关对这批内容持续返回非 200，重试后仍失败，按最保守口径计为 FN。
- 若只统计**取得有效响应的 125 道**，Recall 为 **62.40%**。
- 平均耗时：错题 56.8 s（首轮）／干净题 26.9 s。符号规则命中的 17 道为 0.1 ms。

### 6.5 与 Dev Set B 的关系

| 指标 | Dev Set B（被污染） | **Held-out v2（干净）** | 差异 |
|---|---:|---:|---:|
| Recall | 52.78% | **56.93%** | +4.15 |
| Precision | 98.96% | **97.50%** | −1.46 |
| F1 | 0.6884 | **0.7189** | +0.031 |
| FPR | 1.67% | **3.33%** | +1.66 |

结论：**在 Dev B 上做的优化没有导致 Held-out 性能崩塌，v2 的 F1 甚至略高于 Dev B。** 换言之，之前的迭代没有严重过拟合到 Dev B 的具体条目——这与"概念反转规则表是逐条对着 Dev B 的 gold 写的"这一事实并不矛盾，因为该规则表在 v2 上只命中 0 次（v2 的 6 道事实题全部走流水线），说明它对 v2 没有作弊收益。

需要诚实指出：v2 上 `factual_logical` 仍只有 16.7%（1/6），`unsolvable` 16.7%（1/6），这两类样本量小且是真实短板。

## 七、结论与后续展望

1. **已达成目标**：
   - 彻底解决了调用时间瓶颈（17 道题由符号规则 0.1ms 拦截，知识库单次检索仅 13.6ms）；
   - 在唯一干净的留出集上取得 **Precision 97.50%、FPR 3.33%、Recall 56.93%、F1 0.7189**；
   - 揭示了确定性符号规则（Symbolic Linter）在结构排版上的卓越泛化力（留出集 94.4%），以及**元数据契约缺失会导致题型类任务制度性漏报**这一工程发现；
