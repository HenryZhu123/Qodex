## 2. 基线测试（无知识库）

**配置**：`gpu-qwen3.8-27b`，temperature=0，seed=42，pinning 提示词按任务分派。

| 错误类型 | 检出率 | 定位命中率 |
|---|---:|---:|
| `typo` 错别字 | 90% | 85% |
| `answer_leakage` 答案泄露 | 75% | 75% |
| `option_structure` 选项结构 | 75% | 50% |
| `unsolvable` 题目无解 | 65% | 55% |
| `punctuation` 标点符号 | 55% | 40% |
| `ambiguity` 语义不清 | 40% | 20% |
| `missing_info` 信息缺失 | 30% | 15% |
| `factual_logical` 事实/逻辑错误 | 30% | 30% |
| `type_mismatch` 题型不一致 | 10% | 5% |

**结论**：平均约 52%，仅 `typo` 达到 Proposal 要求的 90% 门槛。

## 3. 知识库消融实验

**知识库**：4 本教材，2512 chunks。

| 学科 | 教材 | chunks |
|---|---|---:|
| 数据结构 | 严蔚敏《数据结构（C语言版）》第2版 | 411 |
| 计算机组成 | 谭志虎《计算机组成原理》 | 625 |
| 操作系统 | 汤小丹《计算机操作系统（慕课版）》 | 601 |

> 注：网络第 8 版为纯扫描件（504 页无文字层），改用第 7 版。

检索使用 FTS5 + bm25，抽查 5 个查询全部命中相关章节。

**结果**：

| 条件 | 检出率 |
|---|---:|
| 无知识库 | 56% |
| 有知识库（证据放入 `reference`） | 59% |
| Δ | **+3%** |

分类别：

| 错误类型 | Δ 检出率 |
|---|---:|
| `type_mismatch` | +15% |
| `punctuation` | +15% |
| `option_structure` | +10% |
| `answer_leakage` | +5% |
| `missing_info` | 0% |
| `ambiguity` | 0% |
| `factual_logical` | 0% |
| `unsolvable` | −5% |
| `typo` | −10% |

**结论**：增益 +3%，远低于评估文档设定的 +8% 合格线。对最需要外部知识的两类（`factual_logical`、`missing_info`）**增益为零**。

## 4. 知识库消融实验（修改提示词后）

**改动**：前置一段"教材证据库"指令，明确要求用 `reference` 作为事实依据判断题目对错，覆盖原提示词"不得对 reference 报错或评价"的约束。

**结果**：

| 条件 | 检出率 |
|---|---:|
| 无知识库 | 48% |
| 有知识库（KB-aware 提示词） | 41% |
| Δ | **−7%** |

**结论**：放开 `reference` 使用约束后，检出率反而下降。

**诊断**：不是提示词挡住了证据使用。抽查推理记录，模型**根本没有去读 `reference`**。它在既定推理路径上就能得出"无错"的结论，没有动机去查外部证据。

## 5. 求解验证实验（小范围）

**假设**（由用户提出）：`factual_logical` 与 `missing_info` 这两类错误无法通过读题发现，必须在解题过程中暴露。因此应让模型先解题再判断。

**实现**：编写"求解验证"提示词，要求模型按 条件建模 → 求解 → 比对归因 → 证据核验 四步执行。

**结果**（每类 3 条）：

| 条件 | `factual_logical` 检出 | `missing_info` 检出 |
|---|---:|---:|
| 直接检查 | 67% | 67% |
| 求解验证 | 33% | 33% |
| 求解验证 + 知识库 | 33% | 0% |

**结论**：求解验证**显著降低**了检出率。

**原因**（从推理记录观察）：

1. **合理化倾向**：模型发现矛盾后，倾向于脑补前提让题目成立
   - 例：把拥塞窗口改成 0B 后，模型写"若题目意指从 0 开始慢启动，通常第一个 ACK 使 cwnd 变为 2"，而非判定条件有误
2. **推理消耗注意力**：token 用在计算上，没有余力质疑题面
3. **提示词未禁止合理化**：只要求"推导失败要归因"，未说"不要为矛盾找借口"

---

## 6. 核心结论

### 6.1 审校模型的本质

**它是"读题自洽性检查器"，不是"事实核对器"。**

| 类型 | 检出率 | 机制 |
|---|---:|---|
| 字面异常（`typo`） | 90% | 读题即可发现 |
| 题内结构异常（`answer_leakage`、`option_structure`） | 75–85% | 读题即可发现 |
| 需外部事实（`factual_logical`） | 30% | 不做核对 |
| 缺失后仍通顺（`missing_info`） | 30% | 无异常可发现 |

### 6.2 知识库未生效的原因

不是检索质量问题（检索已验证准确），而是**审校流程没有设计成"用证据核对题目"**。模型在规定路径上就能自洽地得出"无错"，没有调用外部证据的动机。

### 6.3 对 Proposal 的影响

Proposal 假设"知识库能提升审校质量"。**当前架构下该假设不成立。**

这是一个有价值的负面结果，应如实记录。
