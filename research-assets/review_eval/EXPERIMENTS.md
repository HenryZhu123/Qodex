|---|---:|---:|

| `unsolvable` 题目无解 | 65% | 55% |
| `punctuation` 标点符号 | 55% | 40% |
| `ambiguity` 语义不清 | 40% | 20% |

| `factual_logical` 事实/逻辑错误 | 30% | 30% |
| `type_mismatch` 题型不一致 | 10% | 5% |

**结论**：平均约 52%，仅 `typo` 达到 Proposal 要求的 90% 门槛。

## 4. 知识库消融实验（修改提示词后）

**改动**：前置一段"教材证据库"指令，明确要求用 `reference` 作为事实依据判断题目对错，覆盖原提示词"不得对 reference 报错或评价"的约束。

**结果**：

| 条件 | 检出率 |
|---|---:|
| 无知识库 | 48% |
| 有知识库（KB-aware 提示词） | 41% |
| Δ | **−7%** |

**结论**：放开 `reference` 使用约束后，检出率反而下降。

**诊断**：不是提示词挡住了证据使用。抽查推理记录，模型**根本没有去读 `reference`**。它在既定推理路径上就能得出"无错"的结论，没有动机去查外部证据。

## 5. 求解验证实验（小范围）

**假设**（由用户提出）：`factual_logical` 与 `missing_info` 这两类错误无法通过读题发现，必须在解题过程中暴露。因此应让模型先解题再判断。

**实现**：编写"求解验证"提示词，要求模型按 条件建模 → 求解 → 比对归因 → 证据核验 四步执行。

**结果**（每类 3 条）：

| 条件 | `factual_logical` 检出 | `missing_info` 检出 |
|---|---:|---:|
| 直接检查 | 67% | 67% |
| 求解验证 | 33% | 33% |
| 求解验证 + 知识库 | 33% | 0% |

**结论**：求解验证**显著降低**了检出率。

**原因**（从推理记录观察）：

1. **合理化倾向**：模型发现矛盾后，倾向于脑补前提让题目成立
   - 例：把拥塞窗口改成 0B 后，模型写"若题目意指从 0 开始慢启动，通常第一个 ACK 使 cwnd 变为 2"，而非判定条件有误
2. **推理消耗注意力**：token 用在计算上，没有余力质疑题面
3. **提示词未禁止合理化**：只要求"推导失败要归因"，未说"不要为矛盾找借口"

## 6. 干净题误报基线

**目的**：之前只有错题，无法判断"检出"是真实能力还是乱报。本次补充干净题，测量误报率。

**数据**：从 408 未使用的 471 道原题中抽取 100 道，清洗后取 60 道参与测试。

清洗内容：
- 去除 PDF 着重号 `．`（如「不．符合」）：7 处，会被误判为标点错误
- 去除占位符 `＿`：3 处
- 按内容重新判定学科：29 条原按题号机械映射的标签有误（如排序题被标为计算机组成）

**配置**：60 题 × 9 个检测任务 = 540 次调用。

| 检测任务 | 误报数 | 误报率 |
|---|---:|---:|
| `ambiguity` 语义不清 | 16 | **27%** |
| `punctuation` 标点符号 | 13 | **22%** |
| `missing_info` 信息缺失 | 7 | 12% |
| `unsolvable` 题目无解 | 5 | 8% |
| `typo` 错别字 | 4 | 7% |
| `option_structure` 选项结构 | 0 | 0% |
| `type_mismatch` 题型不一致 | 0 | 0% |
| `answer_leakage` 答案泄露 | 0 | 0% |
| `factual_logical` 事实/逻辑错误 | 0 | 0% |
| **合计** | **45** | **8%** |

**31/60 的干净题至少被一个任务误报（52%）。**

### 6.1 检出率与误报率的对比

| 错误类型 | 检出率 | 误报率 | 判断 |
|---|---:|---:|---|
| `typo` | 90% | 7% | 明显有效 |
| `answer_leakage` | 75% | 0% | 有效 |
| `option_structure` | 75% | 0% | 有效 |
| `unsolvable` | 65% | 8% | 有效 |
| `punctuation` | 55% | 22% | 勉强 |
| `ambiguity` | 40% | **27%** | **近乎无区分力** |
| `missing_info` | 30% | 12% | 弱 |
| `factual_logical` | 30% | 0% | 只漏报，不误报 |
| `type_mismatch` | 10% | 0% | 严重漏报 |

### 6.2 两个新结论

**`ambiguity` 缺乏区分能力**：误报率 27% 与检出率 40% 十分接近，说明它报出的问题中很大比例是噪声。

**`factual_logical` 是"零误报 + 低检出"**：从不误报，但只检出 30%。该任务过于保守，模型默认题目无问题。这为"加入怀疑条件"的改进提供了安全空间——基线误报为 0，即使提升到 10% 仍可接受。

## 7. 核心结论

### 7.1 审校模型的本质

**它是"读题自洽性检查器"，不是"事实核对器"。**

| 类型 | 检出率 | 机制 |
|---|---:|---|
| 字面异常（`typo`） | 90% | 读题即可发现 |
| 题内结构异常（`answer_leakage`、`option_structure`） | 75–85% | 读题即可发现 |
| 需外部事实（`factual_logical`） | 30% | 不做核对 |
| 缺失后仍通顺（`missing_info`） | 30% | 无异常可发现 |

### 7.2 知识库未生效的原因

不是检索质量问题（检索已验证准确），而是**审校流程没有设计成"用证据核对题目"**。模型在规定路径上就能自洽地得出"无错"，没有调用外部证据的动机。

### 7.3 求解验证失败的原因

模型存在**合理化倾向**：发现矛盾后优先假设自己理解有误，而非题面有误。若不显式禁止这种措辞，增加推理步骤反而降低检出率。

### 7.4 对 Proposal 的影响

Proposal 假设"知识库能提升审校质量"。**当前架构下该假设不成立。**

这是一个有价值的负面结果，应如实记录。

### 7.5 下一步的安全空间

`factual_logical` 误报基线为 0，是唯一可以放心增加召回的任务。改进应优先在此处试验。
