# 步骤3：Manifest与任务目录

本目录登记冻结训练数据的来源、数据集版本和真实Task Card。Manifest只记录事实和引用，不修改训练集内容。

## 资产

- `来源清单.json`：25个冻结源文件的ID、快照路径、SHA256、字节数、JSONL行数和父来源关系。
- `数据集清单_原版提示词.json`：原版提示词数据，9,800条。
- `数据集清单_微调版提示词.json`：微调版提示词数据，9,595条。
- `任务目录.json`：12个数据集类别和20个真实Task Card的稳定映射、固定 `error_type`、提示词组件及Bundle哈希。
- `验收报告.json`：Schema、文件哈希、计数和交叉引用验收结果。

对应Schema位于 `D:\hyt-agent\数据资产\schemas\v1`。

## 12个类别与20个任务

“法语、英语、德语、日语”是数据集目录类别，不是单一模型任务。它们内部按拼写、标点、语法或逻辑拆成不同Task Card。因此：

- `DatasetManifest.category_counts` 按12个目录类别统计；
- `DatasetManifest.task_counts` 按20个Task Card统计；
- `CanonicalSample.annotation.task_id` 必须使用 `任务目录.json` 中的任务ID；
- `gold.errors[].error_type` 必须匹配该任务的 `fixed_error_type`。

## 来源状态

当前项目文件没有提供逐来源的授权证明、敏感内容检测结果和脱敏版本，因此Manifest如实记录：

```json
{
  "authorization_status": "not_recorded",
  "sensitivity_status": "not_assessed"
}
```

在获得实际记录前，不将其填写为已授权或已完成脱敏。

## 数据质量告警

生成器会检查每条数据的system提示词所属任务和gold中的 `error_type`。不一致记录写入各自DatasetManifest的 `data_quality`，但步骤3不擅自修改标准答案。

这类样本在正式SFT导出前必须修复或排除，否则模型会同时学习“只检查当前任务”和“输出其他错误类型”两套冲突规则。

## 复现与验收

重新生成Manifest：

```powershell
python D:\hyt-agent\Python脚本\build_step3_manifests.py `
  --workspace-root D:\hyt-agent `
  --snapshot-version v1
```

脚本默认拒绝覆盖已有Manifest；确需生成新内容时应使用新的版本目录。`--overwrite` 仅用于当前v1开发校正。

验证Manifest：

```powershell
python D:\hyt-agent\Python脚本\validate_step3_manifests.py `
  --workspace-root D:\hyt-agent `
  --report D:\hyt-agent\数据资产\manifests\v1\验收报告.json
```
